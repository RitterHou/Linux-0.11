# 两阶段引导与 C 内核

这是 `learning` 分支上的独立实验。`main` 分支保留 Linux 0.11 原始源码。

`docs/tour.html` 是一个可交互的介绍网页：启动的八个阶段、中断时栈的变化、分页的地址翻译、任务切换、系统调用、fork、文件系统、shell、管道、写文件和信号都配有一步步演示的动画，头图里还有一个能敲命令的模拟 shell，用浏览器直接打开即可。页面里的地址、i 节点号、块号都取自真实的构建：改了内核或用户程序之后，先 `make`，再运行 `python3 tools/tour_data.py docs/tour.html` 回填。

## 运行

需要 NASM、QEMU、系统自带的 clang，以及 Homebrew 的 lld（macOS 自带的 `ld` 不能链接 ELF）：

```sh
brew install nasm qemu lld
```

在终端执行：

```sh
cd /Users/Ray/Projects/infra/linux-0.11
make run
```

QEMU 打开窗口后应看到：

| 行 | 内容 | 来源 |
| --- | --- | --- |
| 0 | `ABPKCVITUFWE` | `A` 第一阶段；`B` 第二阶段在实模式下调用 BIOS；`P` 第二阶段进入保护模式后写显存；`K` 内核汇编入口 `entry.asm`；`C` C 函数 `kmain()`；`V` 打开分页后通过虚拟地址 `0xC0000000` 写入；`I` 打开中断之后；`T` 开始任务调度之后；`U` 内核第一次收到来自用户态的系统调用；`F` 内核第一次补上缺页（任务 B 第一次用到栈）；`W` 第一次写时复制（fork 之后父进程先写栈）；`E` 第一次从硬盘装入程序（任务 3 exec `/bin/letter`） |
| 1 | `disk: 8192 sectors (4096 KB), QEMU HARDDISK` | 硬盘驱动开机时用 IDENTIFY 命令问出的扇区数和型号，见下文“硬盘”；第一次用到文件系统时，右边接着显示 `minix fs: 128 inodes, 4096 blocks` |
| 2 | `Hello from kmain() in C!` | `kmain()` |
| 3 | `memory: 3830/3840 pages free  page faults: 1  copy-on-write: 2` | 1 MB～16 MB 之间还有几个 4 KB 的物理页空闲，缺页异常补上了几页，写时复制处理了几次，见下文“物理页分配”“缺页处理”和“fork 与写时复制” |
| 4 | `ticks: N        idle: N%      2026-10-19 05:12:33 UTC` | 定时器中断，每秒加 100；右边每秒更新一次上一秒 CPU 空闲的比例，两个任务都在睡眠时接近 100%；最右边是现在的时间（UTC），开机时从 CMOS 读出，每秒刷新 |
| 5 | `paging: on, 0xC0000000 -> 0xB8000` | 分页已打开 |
| 6 | `tasks: ABCABCABC…` | 任务 A（内核态）、任务 B（用户态）和 B 用 `fork` 复制出、再 exec 成硬盘上 `/bin/letter` 的任务 3 都通过 `write` 系统调用写自己的字母，每写一个就 `sleep`，把 CPU 让给别人，所以逐个轮流；写满一行后从行首覆盖 |
| 7 | 平时为空 | 任务结束时的黄色消息，例如 `task 2 killed by #PF page fault: …`、`task 5 killed by signal 2 (SIGINT)` 或 `task 2 exited with code 7` |
| 8～18 | shell 的欢迎语和提示符 `$` | 控制台窗口：shell 和它运行的程序的输出，以及键盘回显，都写在这里；写满后整个窗口向上滚动一行，窗口外的内容不受影响，见下文“终端与 shell” |
| 19～23 | 平时为空 | 出现 CPU 异常时，红底白字的异常面板，见下文“异常” |

开机后控制台窗口里运行着 shell，可以敲命令：`ls /bin`、`cat /hello.txt`、`cd /etc`、`pwd`、`ps`、`echo 文字`、`ls /bin | grep e`、`echo hi > /tmp/a`、`check`、`letter D &`（在后台运行，第 6 行会多出 D，`kill 任务号` 结束它）、`help`、`exit`（init 会再拉起一个 shell）。键盘支持字母、数字、常用符号、空格、回车、退格、左右 Shift、Caps Lock（美式布局）和左 Ctrl 加字母（Ctrl+C 结束前台程序，Ctrl+D 结束输入），暂不支持方向键、Alt 和小键盘。打字前先点一下 QEMU 窗口，让它获得键盘焦点。

关闭 QEMU 窗口，或在启动它的终端按 Ctrl+C，即可退出。修改代码后，先关闭旧窗口，再执行 `make run`。

- `make`：只生成镜像和 `build/kernel.elf`。
- `make test`：在无头 QEMU 中运行全部自动化测试，见下文“自动化测试”。
- `make clean`：删除生成的 `build/` 目录。
- 默认使用 macOS 的 Cocoa 窗口。其他系统可按 QEMU 支持情况设置，例如 `make run QEMU_DISPLAY=gtk`。
- Apple Silicon 本机是 ARM，QEMU 使用 TCG 模拟一台 x86 PC。

## 自动化测试

```sh
make test
```

`tests/test_kernel.py` 只用 Python 标准库。它在后台启动没有窗口的 QEMU，通过 QEMU 监视器读取显存和寄存器、模拟按键，再用系统自带的 `objdump` 查符号地址和反汇编。目前检查：

- 启动后各行的输出；内存中内核的 `.text` 和 `.rodata` 与 `kernel.bin` 一致（`.data` 运行时会被改写，不比较）；处于保护模式，各段寄存器的值正确，GDTR 指向内核自己的 `gdt`。
- 分页已打开，CR3 指向 `page_directory`；用监视器的 `gva2gpa` 逐个检查虚拟地址：`0xC0000000` 映射到 `0xB8000`，第 0 页和 16 MB 以上未映射，其余一一对应。
- 定时器频率约为 100 Hz（允许 90～110）。
- 文件系统（自检 `USER_FS`，由用户程序执行）：读出 `/hello.txt` 的内容；不存在的文件、分量超过 14 个字节的路径打不开；缓冲区是内核地址时 `read` 返回 -1；600 KB 的 `/big` 逐字节正确，要用到 i 节点的二级间接块，读到末尾返回 0；读根目录得到 `hello.txt`、`big`、`etc` 三项；读出子目录里的 `/etc/issue`；`close` 之后 `read` 返回 -1，8 个描述符用光后 `open` 返回 -1，关掉一个又能打开；fork 之后子进程用继承来的描述符读，父进程的读位置跟着往后走。第 1 行显示文件系统的大小。从内核读出缓冲区缓存的统计：未命中略多于 600 次（每块只从硬盘读一次），命中超过 100 次。
- 硬盘（自检 `HD_RW`，由内核任务 A 执行）：第 1 行显示 8192 个扇区和型号；第 0 扇区是 `tools/mkfs.py` 写在引导块里的说明，第 2 扇区是超级块，有 Minix 的魔数 `0x137F`；最后一个扇区能读，读第 8192 扇区返回 -1；写进第 8000 扇区的内容能原样读回；连续读 64 个扇区不到 10 个 tick，读完后任务 A 照常运行。测试给 QEMU 的硬盘带 `snapshot=on`，写入只留在临时文件里。
- 物理页分配（自检 `PAGE_ALLOC`）：开始时 3840 页空闲；从最高的 `0xFFF000` 往下分配；把一页写脏后释放再分配，拿回的是同一页且已清零；一共正好能分出 3840 页，分光后再分得到 0；全部还回去后又是 3840 页，第 3 行跟着更新。同一页释放两次（自检 `DOUBLE_FREE`）时显示 `Kernel panic: trying to free free page` 并停机。
- 直接喂扫描码（自检 `KEYBOARD_EDGE`，不拉起 shell）：按住 Caps Lock 产生的重复按下码只切换一次；输入超出一行后，退格能跨过行首回到上一行行尾。
- 初始化 8259 之前就有一次按键时，键盘之后仍能正常回显（自检内核不拉起 shell，自检 `EARLY_KEY` 在 `pic_init()` 之前等到键盘控制器里有一个字节，故意不读走）。
- 在 shell 里模拟按键：`echo hi 42` 打印 `hi 42`；退格只能删自己敲的字符，删不到提示符；左右 Shift 得到大写字母和 `!@_` 等符号，Caps Lock 只影响字母，与 Shift 同时生效时得到小写。
- `ls /bin` 的输出比窗口高，窗口第 8～18 行按顺序向上滚动，命令那一行滚出窗口，第 0～6 行和第 19～24 行不受影响。
- shell（`test_shell`）：`cat /hello.txt` 打印文件内容；`ls /bin | wc` 得到 `12 48 230`；`cat /hello.txt | grep Minix`、`ps | grep sh`、三段的 `ls /bin | grep e | wc` 都对；`cat /big | wc` 把 600 KB 经过只有一页的管道交给 wc，得到 `2400 7201 614400`；直接运行 `wc`、敲一行再按 Ctrl+D，wc 打印 `1 2 12`；找不到的命令报告 `not found`；`check` 打印 `check ok`；`check crash` 被缺页异常结束，shell 报告 `killed by exception 14`；`ps` 列出 idle、task_a、init、letter、sh 和 ps 自己，状态和父进程都对；这些命令结束后空闲页数回到原样；`letter D &` 在后台运行，打印任务号，第 6 行出现 D；`exit` 之后 init 拉起一个新的 shell，后台的 letter 还在。
- 两个任务都在睡眠时，CPU 交给任务 0：TR 为任务 0 的 TSS 选择子 `0x50`，停在 `kmain()` 的 `hlt` 上，IF 为 1；第 4 行的空闲比例达到 90% 以上。
- GDT 第 6、7 项是 DPL 3 的用户代码段和数据段；只有用户程序所在的页打开了用户位，内核的代码、数据、IDT、TSS 和显存所在的页都没有。
- 任务 B 运行在用户态：它的内核栈顶是从特权级 3 进入系统调用时 CPU 压入的现场（CS 为 `0x33`、SS 为 `0x3B`、返回地址在 `user_main` 内、ESP 在用户空间顶端那一页内、IOPL 为 0），TSS 中的 `ss0:esp0` 指向这个内核栈，它是从分配器拿来的一整页。
- 每个用户任务有自己的页目录，用户栈按需分配：任务 B 的 CR3（从它的 TSS 读出）不是内核的页目录，内核部分的页目录项与内核的相同，内核的页目录里没有用户空间；第 0 行出现 `F`；按 B 的页目录手工查表，用户空间（`0x40000000`～`0x403FFFFF`）只有栈顶那一页映射到分配来的物理页，栈区的其余部分没有映射。监视器的 `gva2gpa` 只按 CPU 当前的 CR3 翻译，查别的任务的地址空间只能自己读页表。
- 用户程序用掉 5 页栈（自检 `USER_DEEP_STACK`）：每页第一次用到时补上；把一页还没碰过的栈交给 `write`，内核读到它时同样补上，`write` 返回 1；`exit(3)` 之后 B 的页全部收回，第 3 行回到 3839 页空闲（只剩任务 A 的内核栈）。用户程序读栈区以外没映射的 `0x50000000`（自检 `USER_WILD_READ`）时，内核不补页，任务 B 因 `#PF`（错误码 4）被结束。
- 写文件（自检 `USER_FSWRITE`）：`O_CREAT | O_EXCL` 遇到已经存在的文件失败；只读打开的不能写、只写打开的不能读、目录不能打开来写；从头写会覆盖，`O_TRUNC` 清空，`O_APPEND` 接在末尾；删掉一个还开着的文件，目录里看不见了，开着的描述符照样能读，关掉以后块和 i 节点才收回；已经存在的目录不能再建，非空目录、根目录和 `.` 删不掉，父目录不存在或名字太长建不了；同一个文件打开两次共用 i 节点，从一个写进去另一个马上读得到。在 shell 里：`echo hello > /tmp/a`、`>>` 追加、`wc < /tmp/a`、`mkdir`、`rmdir`（非空时失败）、`rm`；`cat /big > /tmp/big2` 复制出的文件要用到二级间接块，内容完全一样；删掉之后 `df` 回到原来的数字。
- 当前目录：`pwd` 开始是 `/`；`cd /etc` 之后 `pwd` 打印 `/etc`，`cat issue` 读到 `/etc/issue`，`ls` 不带参数列出 `/etc`，`ls ..` 和 `ls /` 一样；`cd /bin/../etc/./` 之后是 `/etc`；`cd` 到不存在的目录或普通文件报错，当前目录不变；在 `/tmp/sub` 里 `echo rel > note` 写的是 `/tmp/sub/note`；在 `/bin` 里 `./echo`、`../bin/echo` 都能运行；`cd ../../..` 停在 `/`。shell `exit` 之后，init 拉起的新 shell 从 `/` 开始，不是上一个 shell 的 `/etc`。
- 信号（自检 `USER_SIGNAL`）：kill 一个在 sleep 里的子进程，它马上被 SIGTERM 结束，状态是 0x200 加信号编号；忽略了 SIGTERM 的照常睡完、退出；SIGKILL 不能忽略；`kill(0, …)` 发给自己这一组，忽略随 fork 继承；`setsid` 之后自成一组，`kill(-组号, …)` 才发得到；睡在管道上的读者和写者、睡在 waitpid 里的进程都能被结束；读的一头全关了还写，写的进程被 SIGPIPE 结束，忽略了 SIGPIPE 的 write 返回 -1；kill、signal 的参数不对，或者发给内核任务和 init，都返回 -1；给僵尸发信号返回 0；子进程设了处理函数再 kill 自己，处理函数拿到信号编号，kill 照样返回 0，第二次还调用处理函数；睡在管道上被设了处理函数的信号打断，read 返回 -EINTR，程序接着运行；exec 之后，设过处理函数的信号改回默认，忽略的保持忽略；处理函数不在用户的内存里，signal 返回 `SIG_ERR`；一直在用户态空转、不做系统调用的进程也能被 kill 结束（信号在定时器中断返回用户态时处理）；处理函数打断一段汇编，eax、ecx、edx 和 DF 都原样恢复，处理函数里 DF 是 0。在 shell 里：前台的 `letter G`、等终端输入的 `cat`、`cat | wc` 的两段，按 Ctrl+C 都被 SIGINT 结束，回显 `^C`；在提示符上按 Ctrl+C 丢掉正在敲的这一行，重新打出提示符；后台的 letter 不受 Ctrl+C 影响，`kill 任务号` 用 SIGTERM 结束它，`kill -9` 发 SIGKILL；`kill 1`、`kill 2`、`kill 99`、`kill -x 5` 报错；`kill 4` 发给 shell 自己，它忽略 SIGTERM；shell 一直是原来的 4 号任务。
- 时间（自检 `USER_TIME`）：1970-01-01、2000-02-29（闰年）、2100-03-01 和它的前一秒 2100-02-28 23:59:59（2100 年不是闰年）、0xFFFFFFFF（2106-02-07 06:28:15）的换算都对；`time` 从 CMOS 的时钟往后数，睡 1.5 秒多了 1 或 2；新建的文件修改时间是现在，`utime` 改成 12345 读回来就是 12345，往里写东西又变成现在；目录里增删一项，目录的修改时间变成现在；文件的主人和组是 0。在 shell 里：第 4 行和 `date` 显示的时间与宿主机的 UTC 时间差不到 5 秒；`ls -l` 每行是类型和权限、链接数、主人、组、大小、修改时间、名字，程序有执行权限，设备文件是 `c`；新写的文件和 `touch` 出来的文件修改时间就是现在，`chmod 640` 之后是 `-rw-r-----`。
- 硬链接（自检 `USER_LINK`）：link 之后两个名字的 i 节点号一样，链接数是 2，读到的内容一样；从一个名字写进去，另一个马上读得到；删掉一个名字，另一个照常能读，链接数变回 1，块和 i 节点都没收回，两个都删了才收回；开着的文件两个名字都删了也能读，关掉才收回；目录、已经存在的名字（包括 `.` 和 `..`）、不存在的源文件或目录、太长的名字都不能链接；一个文件链接到 250 个名字以后再 link 返回 -1，链接数不会回绕；文件名后面加 `/` 打不开、stat 不到、删不掉，也不能用来新建文件或链接，目录末尾带 `/` 照常能 mkdir、stat、rmdir；`mv` 搬进目录时拼出来的名字超过 127 个字节就报错退出，不截短（截短的名字正好是目录里另一个文件时，会把它删掉）。在 shell 里：`ln` 之后 `ls` 里两个名字的 i 节点号一样，删掉一个另一个照常能读；`mv` 改名、搬进目录、覆盖已有的文件、搬到自己身上什么也不做，目录搬不了。
- 脚本：`sh 脚本` 一行行执行、跳过注释，脚本里的 `cd` 不影响外面的 shell；新建的脚本没有执行权限，exec 不了，`chmod 755` 之后能直接运行，用 `./s` 这样的相对路径也行；`#!/bin/hello one two` 的脚本运行起来是 `hello "one two" 脚本路径 原来的参数…`，参数加起来 16 个刚好放得下，17 个就运行不了；`#!` 后面没有解释器、解释器本身又是脚本，都运行不了；后台运行的脚本，ps 里能看到 sh 和它的 sleep；前台的脚本按 Ctrl+C，sh 和它里面的 sleep 都被结束，脚本的后面几行不再执行。
- dup2 和 fcntl（自检 `USER_FCNTL`）：dup2 出来的描述符和原来的共用读写位置，`dup2(fd, fd)` 什么也不做，新描述符原来开着的先关掉（它是管道写的一头的话，读的一头就读到末尾了）；`F_DUPFD` 找不小于 arg 的最小空闲描述符，`F_GETFL` 取打开方式，`F_SETFL` 加上 `O_APPEND` 以后写的都接在末尾；close-on-exec 设上读得回来，dup 出来的没有，子进程给管道写的一头设上再 exec sleep，父进程马上读到末尾（那时 sleep 还在睡），fork 出的子进程继承它；不存在的描述符、不认识的命令返回 -1。在 shell 里：`nosuch | wc`、`cat /nothing | wc` 的消息直接显示，wc 读到的是空的；`cat /nothing 2>&1 | wc` 数出 1 行；`2>`、`2>>` 写进文件。
- 延迟写回（自检 `USER_SYNC`）：新建一个 3 KB 的文件，缓冲区里多了几块脏的，硬盘上一块也没写；sync 把它们都写回，写回的块数正好对得上，再 sync 一块也不用写；写一个 40 KB 的文件，比 16 个缓冲区还多，换块时脏块先写回；再从头读回来逐字节核对，换出去的块是从硬盘读回来的；删掉再 sync，块和 i 节点都收回。在 shell 里：sync 之后 `df` 显示没有脏块，`echo hi > /tmp/c1` 弄脏 5 块，等上几秒 init 就把它们写回了，写回的块数正好多 5。
- 闹钟（自检 `USER_ALARM`）：`alarm(1)` 之后一直 `sleep(5)`，大约 20 次之后 SIGALRM 来了，处理函数接住，正在睡的 sleep 被打断；alarm 返回还剩几秒（向上取整），`alarm(0)` 取消之后不再响；`pause` 等到闹钟，返回 -EINTR；没设处理函数的子进程被 SIGALRM 结束；fork 出的子进程没有闹钟；exec 之后闹钟还在。在 shell 里：`sleep 2` 睡大约 2 秒后正常退出，`sleep 100` 按 Ctrl+C 被结束，参数不对报用法。
- 堆（自检 `USER_BRK`）：init 的堆从 `0x40000000` 开始；brk 往上挪 8 KB 能写能读；堆和栈之间没要过的地方，子进程一写就被缺页异常结束，brk 不对齐到页时它所在的那一页能用；fork 之后子进程的堆一样大、内容一样，各改各的；低于程序末尾、伸进栈区的 brk 不动；系统调用的缓冲区在没要过的地方，read 返回 -1；exec 之后堆从新程序的 `.bss` 末尾开始，`check brk` 用 malloc 要来 100 KB 能写能读；栈区最低的那个字节能用，再往下一个字节被结束，想把堆推到紧贴栈区推不上去，栈用超了被结束；跨过堆末尾的缓冲区 read 返回 -1；能缩回空堆；用管道喂给 sort 的数据里有 0、0x80、0xFF，排出来的顺序逐字节核对，`-r` 倒过来；sort 读两个文件，前一个末行没有换行也不接在一起；`check malloc` 检查空块合并、和 sbrk 混用、realloc 原地变大和搬家、随机分配和释放两千次。在 shell 里：`sort` 排两行、`ls / | sort -r` 整行倒着排、打不开的文件报错；`cat /big | sort | wc` 得到 `2401 7201 614401`（最后一行补上了换行），`cat /big /big /big | sort | wc`（1.8 MB）和 `sort /big /big | wc` 也都对，结束后空闲页回到原来的数。
- 管道（自检 `USER_PIPE`）：`pipe` 返回最小的两个空闲描述符；写进去的字节原样读出来；子进程往管道里写 10000 个字节，比一页的缓冲区大，写满了就睡下等，父进程边读边核对，写的一头全关了之后读到 0；读的一头关了再写返回 -1；`dup` 返回最小的空闲描述符，和原来的共用读写位置；结束后管道的缓冲区页也收回。
- exec（自检 `USER_EXEC`）：不存在的文件、没有执行权限的文件、目录，exec 都返回 -1，程序接着运行；子进程 exec `/bin/hello from exec`，打印出参数后以 0 退出；`/bin/check` 检查自己的 `.data`（有初值）、`.bss`（全是 0，跨过一页多）、`argc` 和 `argv`，都对就打印 `check ok` 并以 7 退出；`/bin/check crash` 往自己的代码里写，代码页只读，被缺页异常结束（状态 `0x10E`）；第 0 行出现 `E`；所有程序结束后内存全部收回。
- 用户程序写内核变量或执行 `cli` 时，只有任务 B 被结束：第 7 行给出 `#PF`（错误码 7：页存在、写操作、来自用户态）或 `#GP` 以及出错指令的 EIP，不出现异常面板，定时器照常走，第 6 行很快只剩 A，TR 不再出现任务 B 的 `0x60`，任务 B 的内核栈、页目录、栈区页表和栈页全部收回（第 3 行回到 3839 页空闲）；用户程序调用 `exit(7)` 时同样只剩任务 A，第 7 行为 `task 2 exited with code 7`；把内核地址交给 `write` 得到 -1。
- 用户代码页只读：用户程序改写自己的代码（自检 `USER_WRITE_CODE`）时只结束任务 B，错误码 7。
- 任务 B 在用户态空转时注入 NMI（自检 `USER_SPIN`，先用监视器的 `stop` 暂停、确认 CS 为 `0x33` 再注入）：显示异常面板而不是结束任务 B，面板上的 SS、ESP 是用户态的值。
- 任务 A、B 都结束后切回任务 0：定时器照常走，TR 为 `0x50`，CPU 停在 `kmain()` 的 `hlt` 上，CR3 是内核的页目录，3840 页全部空闲；第 6 行为 `AbyeAAAA`（A 写一个字母就去睡，B 趁机写完 `bye` 结束，A 再写完剩下的 4 个）。
- IDT 第 `0x80` 项是指向 `isr_syscall` 的 DPL 3 陷阱门；`getpid`、`write`、`sleep` 和未知调用号的返回值正确，`write` 的内容出现在第 6 行。
- 任务写一个字母就去睡、把 CPU 让给别人：第 6 行 A、B、C 逐个轮流（一行 73 格不是 3 的倍数，写满一圈后新旧字母的交界处有一次两个相同的字母）；用监视器暂停虚拟机，读出输出位置和 `timer_ticks`，三个任务合计约每个 tick 写 1.5 个字母。
- waitpid（自检 `USER_WAIT`）：返回子进程号，把退出码 42 写回父进程的变量；那个变量所在的页 fork 之后由三个进程共用，内核写它时也会先复制，另一个进程看到的仍是原值；16 个任务槽去掉任务 0、A、B 正好能 fork 13 次，第 14 次返回 -1；`waitpid(-1)` 把它们一个个收走；`WNOHANG` 在子进程还没结束时立刻返回 0，等别人的子进程返回 -1；被缺页异常结束的子进程，状态是 `0x10E`。所有子进程收走后内存回到只剩任务 A 的内核栈。
- fork：任务 3 有自己的页目录和内核栈；父子都写过栈之后，栈顶映射到不同的物理页，页表项都已改回可写；用户代码那一页父子共用。自检 `USER_FORK`：子进程把栈上的变量改成 99，父进程看到的仍是 7；`fork()` 在父进程返回 3、在子进程返回 0；父进程不等子进程就结束时，已经结束的子进程也被收走，内存全部收回。
- 抢占（自检 `USER_SPIN`，用户程序一直空转、从不睡眠）：任务 A 只能在任务 B 的时间片用完后运行，约每 20 个 tick 写一个字母；空闲比例降到 10% 以下。
- 寄存器设为已知值后执行 `ud2`：异常面板显示 `#UD`，EAX～EBP、EIP（`ud2` 的地址）、各段寄存器、CR3 都与预期一致，ESP 落在内核栈内，EFLAGS 的 IF 为 1。
- 除以零显示 `#DE`，EIP 正好指向 `div` 指令；触发未填写的 IDT 表项显示 `#GP`，错误码为 `0x182`。
- 读未映射的 `0xD0000000` 显示 `#PF`，错误码 0，CR2 为该地址；写空指针显示 `#PF`，错误码 2（写操作），CR2 为 0。
- 坏指针不会让内核停机（`check badptr`）：把程序自己代码页的地址交给 `read`、`waitpid`、`stat`、`taskinfo`、`pipe`，都返回 -1，程序照常运行。shell 一行 17 个参数时只取前 16 个，多余的不会并进最后一个参数。
- 不接硬盘开机（把 `floppy.img` 复制到一个没有 `hd.img` 的目录里）：第 1 行是 `disk: none`；任务 3 exec 不了 `/bin/letter`，用内核映像里的代码写 C；shell 起不来，init 隔 1 秒才重试，2 秒里写时复制的次数只多几次。
- 把 loader 所在的 `0x8000`～`0x81FF` 清零后，定时器照常工作：内核已不再依赖 loader 的 GDT。
- 内核被撑到约 90 个扇区、跨越 3 个柱面时，loader 也能完整读入：末尾的标记能读到，`0x10000` 起的内存与 `kernel.bin` 一致。
- 把 DS、ES、FS、GS 换成一个基址为 1 MB 的数据段后空转，定时器照常工作，空闲时这些段寄存器仍是原来的值：中断入口会换成内核段，返回前再恢复。这里不用空选择子测试，因为 QEMU 的 TCG 模拟不检查通过空选择子访问内存，换不换段都看不出区别。

后面几项需要故意制造异常或破坏内存。测试脚本会用 `make BUILD=build/selftest/<名称> SELFTEST=<名称>` 另外构建自检内核：`SELFTEST` 非空时，`selftest.c` 中对应的代码会被编译进去，在打开中断后触发异常。正常构建不定义 `SELFTEST`，`selftest_run()` 是空函数。

全部测试约需 25 秒（自检内核已构建过时）。任何一项失败时脚本以非 0 状态退出，并打印期望值与实际值。测试脚本使用 Makefile 中的 `QEMU` 变量，可以用 `make test QEMU=/path/to/qemu-system-i386` 换成别的 QEMU。

脚本自身也做了防护：监视器在 5 秒内没回到提示符就报错，而不是把半截输出当成下一条命令的结果；读内存时核对每一行的地址；QEMU 的错误输出写进日志文件，QEMU 退出时附在失败信息里；一项测试中的意外异常只算这一项失败；正常内核没能启动时，依赖它的各项记为失败，自检内核的各项照常运行。

## 启动过程

1. BIOS 读取软盘的第一个扇区，加载到物理地址 `0x7C00`，检查 `55 AA` 签名后执行。
2. `boot.asm` 初始化段寄存器和栈，保存 BIOS 通过 `DL` 传入的启动盘编号，清屏并打印 `A`。
3. 第一阶段调用 `int 0x13` 的 `AH=0x02` 功能，从柱面 0、磁头 0、扇区 2 读取一个扇区到 `0000:8000`。
4. 若返回的进位标志 `CF=1`，先复位磁盘系统再重试；3 次都失败则打印 `E` 并停机，画面为 `AE`，此时不会执行第二阶段。真实软驱刚上电或刚换盘时，第一次读常常失败。
5. 若读取成功，执行远跳转 `jmp 0x0000:0x8000`，开始执行 `loader.asm`。
6. 第二阶段保存 `DL` 中的启动盘编号，沿用栈和文本模式，不清屏，用 BIOS 接着打印 `B`。
7. 第二阶段用 `int 0x13` 的 `AH=0x08` 功能查询软盘的几何参数，再从 LBA 2（CHS 扇区 3）起逐个扇区读取 `KERNEL_SECTORS` 个扇区到 `0x10000` 起的内存，读取时把 LBA 换算成柱面、磁头、扇区号，可以跨越磁道和柱面。某个扇区读失败时先复位磁盘系统再重试，3 次都失败则打印 `E` 并停机，画面为 `ABE`。
8. `cli` 关闭中断，再通过 `0x92` 端口打开 A20 地址线。
9. `lgdt` 加载 GDT，置 CR0 的 PE 位，然后远跳转 `jmp 0x08:protected_mode`，用代码段选择子重新装载 CS，开始执行 32 位代码。
10. 把 DS、ES、FS、GS、SS 都设为数据段选择子 `0x10`，ESP 设为 `0x7C00`。
11. BIOS 在保护模式下不可用，直接向 VGA 文本显存 `0xB8004` 写入字符 `P` 和属性 `0x07`。
12. 执行 `jmp eax` 跳到 `0x10000`，即内核入口 `_start`（`entry.asm`）。
13. `_start` 把 ESP 换成内核自己的 4 KB 栈，把 `.bss` 清零，向 `0xB8006` 写入 `K`，然后 `call kmain`。
14. `kmain()`（`kernel.c`）从第 0 行第 4 列写入 `C`，再换两行打印 `Hello from kmain() in C!`。
15. `kmain()` 调用 `gdt_init()` 换上内核自己的 GDT，调用 `idt_init()` 装好 IDT，再调用 `paging_init()` 建立页表并打开分页，然后通过虚拟地址 `0xC0000000` 在第 0 行写入 `V`，在第 5 行写出分页信息；`mem_init()` 把 1 MB～16 MB 的物理页交给分配器，在第 3 行写出空闲页数。
16. `kmain()` 调用 `pic_init()`、`keyboard_init()`、`timer_init(100)`、`sched_init()`，重新设置 8259、读光键盘控制器里残留的字节、把定时器设为每秒 100 次、建好任务 A（内核态）和任务 B（用户态）的 TSS，然后写出第 4、6、8 行的标签。
17. `sti` 打开中断，在第 0 行写入 `I`，调用 `selftest_run()`（正常构建中为空）。
18. `sched_start()` 打开调度，在第 0 行写入 `T`。下一个定时器中断就从任务 0 切到任务 A。任务 A、B 每写一个字母就 `sleep(2)`，把 CPU 让给对方；两个都睡着时切回任务 0，CPU 停在 `kmain()` 的 `hlt` 上，等定时器中断叫醒它们。第一次切到任务 B 时 CPU 直接进入特权级 3。`user_main()` 的第一条指令就是 `pushl %ebp`，栈顶那一页还没有映射，触发缺页，内核分一页映射上去，在第 0 行第 9 列写入 `F`；接着 B 执行第一个系统调用 `getpid()`，内核在第 8 列写入 `U`。`F` 其实比 `U` 先出现，两个字母的列号是固定的。

19. init（任务 B）fork 出任务 3，它 exec 硬盘上的 `/bin/letter C`：第一次用到文件系统，读超级块、在第 1 行显示文件系统的大小；装入成功，在第 0 行第 11 列写入 `E`。init 再 fork 出任务 4，把它的 0、1、2 号描述符接到 `/dev/tty0`，exec `/bin/sh`：控制台窗口里出现欢迎语和提示符。

内核必须在第 7 步、也就是仍处于实模式时读入：进入保护模式后 BIOS 的 `int 0x13` 就不能再用了，而我们没有软驱的驱动（只有硬盘的）。Linux 0.11 也是这样做的：`bootsect.s` 在实模式下把内核读到 `0x10000`（`SYSSEG = 0x1000`），`head.s` 设好栈后再跳进 C 的 `main()`。

现在内核已经能响应定时器、键盘中断和 CPU 异常，打开了分页；一个内核态任务和一个用户态任务轮流运行，等待时把 CPU 让出去，用户态任务只能通过 `int 0x80` 系统调用请内核做事。

## 内核的构建过程

```text
内核的 .asm 文件 ──nasm -f elf32──▶ *.o ─┐
                                        ├─ ld.lld + linker.ld ─┬─▶ kernel.bin（写进软盘）
内核的 .c 文件 ────clang -c────────▶ *.o ─┘                      └─▶ kernel.elf（带符号，供调试）
```

- `clang --target=i386-elf` 让系统自带的 clang 生成 32 位 x86 的 ELF 目标文件，而不是 macOS 程序。其他编译选项的作用写在 `Makefile` 的注释里，核心是 `-ffreestanding`：没有标准库，不能用 `printf`，也没有 `main` 入口。
- `linker.ld` 把链接地址定为 `0x10000`，并把 `entry.asm` 的 `.text.entry` 段排在最前面。loader 不解析任何文件格式，只是把 `kernel.bin` 原样读到 `0x10000` 后跳过去，所以文件的第一个字节必须是 `_start`。脚本末尾的 `ASSERT` 在这一点不成立时让链接失败。
- `ld.lld --oformat=binary` 输出去掉 ELF 头的纯机器码，作为 `kernel.bin`。`.bss` 在最后，不占文件空间。
- `kernel.elf` 不进软盘，可以用系统自带的 `objdump -d build/kernel.elf` 反汇编，或用 `objdump -t build/kernel.elf` 查看各符号的地址。
- 修改 `kernel.h`、`io.h` 或 `Makefile` 后，所有 C 文件都会重新编译。

一次构建中各段的地址如下（具体数值随代码变化，以 `objdump -h build/kernel.elf` 为准）：

| 段 | 地址 | 内容 |
| --- | --- | --- |
| `.text` | `0x10000` 起，约 5.5 KB | `_start` 在最前，后面是 48 个中断入口和各个 C 函数 |
| `.rodata` | 紧随 `.text` | 中断入口地址表、异常名称、扫描码表、字符串 |
| `.data` | 紧随 `.rodata` | 有非 0 初值的全局变量，例如回显窗口的最后一行 `window_bottom` |
| `.user` | 下一个 4 KB 边界起，1 页 | 用户程序 `user.c` 的代码和只读数据，对用户态只读；`__user_data` 起是数据，现在为空。用户栈不在这里，它在虚拟地址 `0x40000000` 起的 4 MB 里按需分配 |
| `.bss` | `.user` 之后，约 38 KB | 4 KB 内核栈（任务 0 用）、2 KB 的 IDT、内核的页目录和 5 张页表（共 24 KB）、16 个 TSS 和任务表、3840 字节的 `mem_map`、光标位置、`timer_ticks` 等。其余任务的内核栈和用户任务的页目录都是运行时从分配器拿的页。页目录和页表要求 4 KB 对齐，`.bss` 从 4 KB 边界开始 |

## 为什么要清零 .bss

C 语言规定，没有初值的全局变量和 `static` 变量初值为 0。编译器把它们放进 `.bss` 段，`kernel.bin` 里不存它们的内容，以节省空间。在普通程序里，由操作系统在加载时清零；我们的内核没有人帮忙，只能在 `_start` 中自己用 `rep stosb` 清零。

现在依赖这一点的有 `timer_ticks`（ticks 从 0 开始数）、`keyboard.c` 中的 `line_length`、IDT 中没有填写的表项（除第 `0x80` 项外的 48～255 号，全 0 才是确定的“非法门”），以及页目录中没有用到的 1019 项：它们的存在位必须是 0，否则 CPU 会把垃圾当成页表地址，访问那些虚拟地址时读写到任意物理内存。

在 QEMU 中去掉清零，目前看不出差别：SeaBIOS 开机自检时会把常规内存清零，开机前写进内存的值到内核运行时都已变成 0；loader 只读入 `kernel.bin` 本身占用的扇区，不会读到 `.bss` 所在的内存。第 3 步（提交 `a716a38`）的 README 中有一个能看到效果的实验：当时光标变量没有被显式赋值，又位于读入范围内，往镜像里写入垃圾后输出就乱了。在真实硬件上，或由别的引导程序加载时，内存不一定是 0，所以清零不能省。

## 中断

### 中断的处理路径

```text
定时器 / 键盘 ──IRQ──▶ 8259 ──中断号 0x20 / 0x21──┐
                                                ├─▶ CPU 查 IDT ─▶ isr.asm 的 isrN ─▶ interrupt_dispatch()
CPU 异常（除零、#GP 等）──中断号 0～31─────────┘
```

1. CPU 收到中断号 N，在 IDT 中取出第 N 项，跳到对应的入口 `isrN`（`isr.asm`）。中断门会自动清除 IF，处理期间不会再被别的中断打断。CPU 自动压入 EFLAGS、CS、EIP，少数异常还会压入错误码。
2. `isrN` 对没有错误码的中断补压一个 0，再压入中断号 N，然后跳到公共部分 `isr_common`。这样所有中断的栈布局都相同。
3. `isr_common` 用 `pushad` 保存通用寄存器，再保存 DS、ES、FS、GS，并把它们换成内核数据段 `0x10`：中断可能打断任何代码，那时的段寄存器不一定是内核的，而 CPU 只自动切换 CS（以及特权级变化时的 SS）。然后把栈顶地址作为参数调用 `interrupt_dispatch()`。栈上的内容就是 `kernel.h` 中的 `struct interrupt_frame`。
4. `interrupt_dispatch()`（`interrupt.c`）按中断号分发：0～31 号是异常，来自用户程序的交给 `user_exception()` 结束该任务，其余交给 `exception_panic()` 显示面板并停机（见下文“用户态出错只结束出错的任务”）；0x80 交给 `syscall_dispatch()`；0x20 交给 `timer_handle()`，0x21 交给 `keyboard_handle()`。外设中断先向 8259 发送 EOI 再处理，原因见下文“任务切换”。
5. 回到 `isr_common`，恢复 GS、FS、ES、DS，`popad` 恢复通用寄存器，丢掉中断号和错误码，`iretd` 回到被打断的地方，通常是 `kmain()` 的 `hlt` 循环。

### IDT

IDT 有 256 项，每项 8 字节，放在 `.bss` 中。`idt_init()` 把前 48 项填成 32 位中断门，入口地址来自 `isr.asm` 中的地址表，选择子是内核 GDT 的代码段 `0x08`；第 `0x80` 项是系统调用的入口，见下文“系统调用”；其余各项保持全 0。最后用 `lidt` 把 IDT 的界限和基址装入 IDTR。

全 0 的表项类型字段为 0，不是合法的门描述符。若被触发，CPU 在检查存在位之前就产生 13 号一般保护异常，错误码为 `中断号 × 8 + 2`（第 1 位表示错误来自 IDT）。

### 8259 中断控制器

两片 8259 级联，管理 16 根 IRQ 线：主片负责 IRQ0～7，从片负责 IRQ8～15，从片接在主片的 IRQ2 上。BIOS 把主片映射到中断号 `0x08`～`0x0F`，与 CPU 异常 8～15 重叠：不改的话，每次定时器中断都会被当成 8 号双重错误。`pic_init()` 重新发送 4 个初始化命令字，把 IRQ0～15 映射到 `0x20`～`0x2F`，并只打开 IRQ0（定时器）和 IRQ1（键盘）。Linux 0.11 的 `setup.s` 做的是同样的事。

8259 在送出一个中断后，要等 CPU 回复 EOI（End Of Interrupt），才会送来同级和更低优先级的中断。忘记发 EOI，定时器只会响一次。

### 定时器

8253 定时器的输入时钟是 1.193180 MHz。`timer_init(hz)` 把分频值 `1193180 / hz` 写进通道 0，于是每秒产生 `hz` 次 IRQ0。分频值是 16 位的，所以 `hz` 至少为 19。`timer_handle()` 把 `timer_ticks` 加 1，并刷新第 4 行的数字。Linux 0.11 的 `sched_init()` 用同样的方法设置 100 Hz 的时钟，用来驱动进程调度。

### 键盘

每按下或松开一个键，键盘控制器就把一个扫描码放进 `0x60` 端口，并发出 IRQ1。`keyboard_handle()` 必须读走扫描码，控制器才会送来下一个。扫描码最高位为 1 表示松开。`keyboard.c` 记录左右 Shift 是否按住（要同时处理按下和松开）、Caps Lock 是否打开（每按下一次切换；按住不放时键盘会重复发送按下码，这些重复的按下码不再切换），其余键只处理按下：查普通表或 Shift 表转成字符，交给终端的 `tty_input()`，由它回显、处理退格（见下文“终端与 shell”）；`vga_putc()` 写字符时同时移动屏幕上闪烁的硬件光标。`kmain()` 用 `vga_set_window(8, 18)` 把 `vga_putc()` 限制在第 8～18 行：光标写过第 18 行时，窗口内的行整体上移一行、最后一行清空，第 0～6 行的固定内容和第 19 行以下都不受影响。Caps Lock 只影响字母，与 Shift 同时生效时字母为小写，与真实键盘一致。方向键等扩展键先送一个前缀 `0xE0` 再送一个字节，目前连同后一个字节一起忽略。键盘上的 Caps Lock 指示灯需要向键盘发命令才会亮，这里没有做。

`keyboard_init()` 在 `pic_init()` 之后、打开中断之前，把键盘控制器输出缓冲区里残留的字节读光。若开中断前就有按键（开机时按住某个键，或 BIOS 菜单留下的松键码），这个字节没人读，键盘控制器就让 IRQ1 一直保持高电平；8259 是边沿触发，初始化命令又重置了它的边沿检测，之后再也等不到上升沿，键盘中断就永远不来了。

### 异常

0～31 号是 CPU 异常，目前都无法恢复。`exception_panic()` 在第 19～23 行画一块红底白字的面板，显示异常号、名称和出错那一刻的全部寄存器，然后停机。面板在键盘回显窗口下面，滚动时不会被移走。例如自检 `REGISTER_DUMP` 的面板：

```text
Exception 6 #UD invalid opcode
EIP=0x00011126 CS=0x0008 EFLAGS=0x00010202 error=0x00000000
EAX=0x11111111 EBX=0x22222222 ECX=0x33333333 EDX=0x44444444
ESI=0x55555555 EDI=0x66666666 EBP=0x77777777 ESP=0x00012FF0
DS=0x0010 ES=0x0010 FS=0x0010 GS=0x0010 CR2=0x00000000 CR3=0x00018000
```

- 寄存器的值都取自栈上的 `struct interrupt_frame`，也就是中断入口保存下来的、异常发生那一刻的状态。
- 同一特权级内发生异常时，CPU 不压入 ESP，所以出错时的 ESP 就是栈上 EFLAGS 之后的地址。
- CR2 只在缺页异常时有意义，是出错的虚拟地址。CR3 是页目录的物理地址。
- EFLAGS 中的 `0x10000` 是 RF 位，CPU 在这类故障异常时自动置位。
- 用 `objdump -d build/kernel.elf` 按 EIP 可以找到出错的那条指令。

## 系统调用

程序执行 `int 0x80` 请求内核服务，约定与 Linux 0.11 相同：EAX 是调用号，EBX、ECX、EDX 依次是第 1～3 个参数，返回值放回 EAX。`syscall.h` 定义调用号和 `write()`、`getpid()`、`sleep()` 等包装函数，相当于 Linux 0.11 `include/unistd.h` 中的 `_syscall3` 等宏；内核一侧在 `syscall.c`。

调用的过程：

```text
write(1, &c, 1)                       syscall.h：EAX=0，EBX=1，ECX=&c，EDX=1，执行 int $0x80
  └▶ CPU 查 IDT 第 0x80 项           DPL 3 的陷阱门，跳到 isr_syscall
      └▶ isr_common                  与其他中断相同：保存寄存器，换成内核数据段
          └▶ interrupt_dispatch()    中断号 0x80，交给 syscall_dispatch()；不是外设中断，不发 EOI
              └▶ syscall_dispatch()  按 EAX 查 syscall_table，调用 sys_write(EBX, ECX, EDX)
                  返回值写进栈上保存的 EAX
      ◀── isr_common 用 popad 恢复寄存器，EAX 里就是返回值；iretd 回到 int 的下一条指令
```

- 门的 DPL 决定谁可以用 `int n` 调用它：`int n` 要求当前特权级在数值上不大于门的 DPL。中断门和异常入口都是 DPL 0，用户态程序（特权级 3）执行 `int 0x20` 之类会触发 `#GP`；只有第 `0x80` 项是 DPL 3。Linux 0.11 用 `set_system_gate(0x80, &system_call)` 做同样的设置。
- 第 `0x80` 项用陷阱门而不是中断门：陷阱门进入时不清 IF，系统调用执行期间定时器照常中断，耗时的系统调用不会耽误计时和抢占。
- 栈上保存的 EAX 就是 `struct interrupt_frame` 中的 `eax`。`syscall_dispatch()` 改写它，中断返回时 `popad` 把它装回 EAX，这是把返回值交给调用方的方法。

## 用户态

x86 有 4 个特权级，这里只用 0（内核态）和 3（用户态）。当前特权级（CPL）就是 CS 的低 2 位。任务 A 在特权级 0 运行内核里的 `task_main()`；任务 B 在特权级 3 运行 `user.c` 中的 `user_main()`，它不能执行 `cli`、`hlt`、`in`、`out` 等特权指令，不能访问内核的内存和显存，要做任何事都只能通过 `int 0x80` 请内核帮忙。

| 机制 | 做法 | Linux 0.11 的对应做法 |
| --- | --- | --- |
| 用户段 | GDT 第 6、7 项是 DPL 3 的代码段和数据段，选择子 `0x33`、`0x3B` 的 RPL 也是 3 | 每个进程在 LDT 中有自己的用户段，选择子 `0x0f`、`0x17` |
| 进入用户态 | 任务 B 的 TSS 中 CS、DS 等都是用户段选择子；硬件任务切换装入这个 TSS 时，CPU 直接进入特权级 3 | `move_to_user_mode()` 在栈上构造一个返回现场，用 `iret` 落到特权级 3 |
| 内核栈 | TSS 中的 `ss0:esp0` 指向任务 B 的内核栈（从分配器拿来的一页） | `copy_process()` 把 `esp0` 设为该进程内核栈的顶端 |
| 内存保护 | 页表项的用户位：只有 `.user` 段的页和用户空间里分配了的页可以从特权级 3 访问 | 不靠页表：`head.s` 把前 16 MB（内核在内）都映射成 7（存在、可写、用户）。用户程序碰不到内核，是因为它的代码段、数据段（LDT 中）基址为 进程号 × 64 MB、界限有限，形成的线性地址根本落不到内核那里 |
| 检查用户指针 | 来自用户态的 `write`，`buf` 必须完全落在用户程序的页内或用户空间内（`user_range_ok()`） | 不逐个检查范围：内核通过 FS（用户数据段）用 `get_fs_byte()` 等读写用户内存，用户给的指针按用户段解释，越界由段界限挡住。`verify_area()` 另有用途：内核写用户内存之前预先处理写时复制，因为 386 在特权级 0 不理会页的只读位 |

用户态发生中断或系统调用时，CPU 要先换栈：用户栈不可信，内核不能在上面工作。

```text
用户态（CPL 3）执行 int $0x80
  1. CPU 从当前 TSS 取出 ss0:esp0，把 SS、ESP 换成任务 B 的内核栈
  2. 在内核栈上依次压入用户态的 SS、ESP、EFLAGS、CS、EIP
  3. 从 IDT 第 0x80 项装入 CS=0x08，CPL 变成 0，跳到 isr_syscall
  4. isr_common 保存寄存器，把 DS 等从用户段 0x3B 换成内核段 0x10
     ……处理系统调用……
  5. iretd 弹出 EIP、CS、EFLAGS，发现 CS 的 RPL 是 3，再弹出 ESP、SS，回到用户态
```

`kernel.h` 中的 `struct interrupt_frame` 末尾因此多了 `user_esp`、`user_ss` 两项，只有从用户态进入时才有效。用户程序自己的错误不会走到异常面板（见下文），但用户态时收到 NMI 等硬件异常会显示面板，那时面板据此显示用户态的 ESP 和 SS。

页目录项和页表项都有用户位，CPU 取两者的“与”：前 16 MB 的页目录项都打开了用户位，再由页表项逐页决定，内核的页在页表项中不开用户位。用户程序的代码和数据由链接脚本集中放进 `.user` 段，首尾按 4 KB 对齐，`paging_init()` 只给这几页打开用户位。段内又分成两部分：代码和只读数据在前，数据从下一个 4 KB 边界 `__user_data` 开始；前一部分的页去掉可写位，野指针写到代码上会立刻触发缺页，而不是悄悄改掉代码。用户栈不在 `.user` 段里，见下文“缺页处理”。内核也不能写它们：`paging_init()` 打开了 CR0 的 WP 位，见下文“fork 与写时复制”。`linker.ld` 用 `EXCLUDE_FILE(*user.o)` 把 `user.o` 排除在内核的 `.text`、`.rodata`、`.data` 之外；`EXCLUDE_FILE` 只作用于紧跟其后的一个段名，所以每个段名前都要写一次。

内核能读写所有内存，所以系统调用不能盲目相信用户传来的指针。若不检查，用户程序把内核地址交给 `write`，内核就会替它把内核内存印出来。系统调用碰用户内存之前，先调用 `user_range_ok()`（要读）或 `user_write_ok()`（要写），由 `prepare_user()` 检查并准备好这段内存：

- 它必须完全落在用户自己的内存里：内核映像里的用户程序那几页（代码只读），或者当前任务的用户空间，否则返回 -1；
- 用户空间里还没映射的页，当场补上；要写的话，写时复制的页当场复制好；要写只读的代码页，或者内存不够，返回 -1。

准备好以后，内核读写这段内存就不会再缺页。要是等到复制数据时才缺页、才发现页是只读的或者内存不够，内核已经在特权级 0 里，没法只结束这个程序，只能停机：审查时就发现，把程序自己代码页的地址交给 `read`，曾经能让整个系统停机。一个任务的页表只有它自己会改，准备好之后到用完之前不会有别人把页拿走。Linux 0.11 的 `verify_area()` 也是在内核写用户内存之前，先把写时复制的页处理好。

### 用户态出错只结束出错的任务

内核自己出错时无法恢复，只能显示异常面板并停机；但用户程序出错是用户程序的事，不应该拖垮整个系统。`interrupt_dispatch()` 收到 0～31 号异常时，如果是缺页，先交给 `handle_page_fault()`：用户空间里的页还没分配是正常情况，补上一页就返回（见下文“缺页处理”）。其余情况先看栈上保存的 CS：

- 低 2 位是 3，说明出错时在用户态。`user_exception()` 在第 7 行用黄字写出 `task 2 killed by #PF page fault: EIP=… error=…`，然后调用 `sched_exit(0x100 | 异常号)` 结束这个任务。
- 否则是内核自己出错，照旧显示异常面板并停机。
- 例外是 NMI（2 号）、双重错误（8 号）和机器检查（18 号）：它们来自硬件，或者表示内核处理异常时又出了错，与用户程序无关，即使发生时 CPU 恰好在用户态，也照样显示异常面板。这时面板上的 CS、SS、ESP 是用户态的值。

`sched_exit(status)` 结束当前任务，切到下一个能运行的任务，不再返回，见下文“exit 与 waitpid”。`exit(code)` 系统调用走的是同一条路，只是第 7 行写 `task 2 exited with code 7`，留给父进程的状态是退出码，而被异常结束的是 0x100 加异常号。Linux 0.11 的 `kernel/traps.c` 中，各异常处理函数调用 `die()`：打印寄存器后调用 `do_exit(11)` 结束当前进程（11 是 `SIGSEGV` 的编号）；`do_exit()` 还要释放内存页、关闭文件、通知父进程，最后同样调用 `schedule()` 切走。

## 任务切换

`sched.c` 用 x86 的硬件任务切换让任务 A、B 轮流运行，与 Linux 0.11 的做法相同。

- 每个任务有一个 TSS（任务状态段，104 字节），里面存着这个任务的全部寄存器：EIP、ESP、EFLAGS、通用寄存器、段寄存器和 CR3。切换时 CPU 保存前几类寄存器，但 CR3 只从新 TSS 装入、不保存回旧 TSS，所以每个 TSS 的 CR3 都要预先填好，包括任务 0 的。GDT 从第 10 项起每个任务槽一个 TSS 描述符，任务 n 的选择子是 `(10 + n) × 8`：任务 0、A、B 分别是 `0x50`、`0x58`、`0x60`。
- 任务表有 16 个槽，槽号就是任务号，与 Linux 0.11 的 `task[NR_TASKS]` 相同（它有 64 个）。除任务 0 外，每个任务的内核栈是从分配器拿来的一页；用户任务还有自己的页目录：`new_page_dir()` 分一页，照抄内核的页目录，内核部分的项指向同一批页表，用户空间那一项各管各的。TSS 里的 CR3 就是这个页目录，硬件任务切换装入 TSS 时 CR3 跟着换，换任务就换了地址空间。内核任务 A 和任务 0 用内核的页目录。Linux 0.11 不换页目录，所有进程共用一份，靠每个进程的段基址（进程号 × 64 MB）把各自的线性地址错开。
- 任务 0 就是 `kmain()` 自己。`sched_init()` 用 `ltr 0x50` 把它登记为当前任务，CPU 第一次切换时才知道把当前寄存器存到哪里。任务 A、B 的 TSS 预先填好入口地址、各自内核栈的栈顶、`EFLAGS = 0x202`（IF=1）、内核段选择子和当前的 CR3。
- `switch_to(n)` 执行一条远跳转 `ljmp` 到任务 n 的 TSS 选择子。CPU 把当前寄存器存进当前任务的 TSS，再从目标 TSS 装入全部寄存器，于是目标任务从它上次被切走的地方接着运行；第一次运行的任务从入口开始。Linux 0.11 的 `switch_to` 宏也是一条 `ljmp`。
- 定时器中断每次调用 `schedule()`：先叫醒睡到时间的任务；此刻运行的是空闲的任务 0，就马上切到能运行的任务；否则当前任务用完时间片（20 个 tick）才按 1 → 2 → 1 … 的顺序切到下一个能运行的任务。后一种是抢占：一直不睡的任务也会被切走，别的任务照样有机会运行。Linux 0.11 的 `do_timer()` 也调用 `schedule()`，但先有一句 `if (!cpl) return;`：中断发生在内核态时不切换，内核代码从不被抢占。这里不同，任务 A 本身在内核态运行，系统调用又经陷阱门开着中断执行，内核代码随时可能被切走，所以共享数据要像 `task_write_char()` 那样关中断保护。下一个任务就是自己时不切换：远跳转到自己的 TSS 会因为它处于“忙”状态而触发 `#GP`。
- `sleep(ticks)` 调用 `sched_sleep()`：把当前任务标为睡眠、记下醒来的时刻，立刻切到下一个能运行的任务，没有就切回任务 0。到时间后，定时器中断里的 `schedule()` 把它改回能运行，轮到它时从切走的地方接着执行，系统调用随之返回。标记和切走之间关中断，免得定时器中断插进来。Linux 0.11 的 `sleep_on()` 也是先改 `current->state`，再调用 `schedule()`；它的 `schedule()` 每次先检查各进程的 `alarm` 是否到期，到期就发 `SIGALRM` 把它叫醒，与这里每个 tick 检查醒来时刻类似。
- 任务 0 是空闲任务，不睡也不结束：任务 A、B 都在睡眠或都已结束时切回它，它从上次被切走的定时器中断里返回，停在 `kmain()` 的 `hlt` 循环中，等下一个定时器中断。测试 `ALL_EXIT` 让任务 A、B 都调用 `exit`，检查此时 TR 为 `0x18`、CR3 仍是页目录、定时器照常工作。Linux 0.11 的 `main()` 最后是 `for(;;) pause();`，任务 0 也只在没有别的进程能运行时才被调度。
- 每个 tick，`schedule()` 看一眼此刻是谁在运行，是任务 0 就记一次空闲，每秒在第 4 行显示一次空闲比例。正常运行时接近 100%：两个任务每 2 个 tick 才醒来写一个字母，其余时间 CPU 都停在 `hlt` 上。Linux 0.11 的 `do_timer()` 用同样的抽样办法，按中断发生在用户态还是内核态，给当前进程的 `utime` 或 `stime` 加 1。
- 任务 A 运行内核里的 `task_main()`，任务 B 运行用户程序 `user.c` 里的 `user_main()`，两者做同样的事：用 `getpid()` 得到任务号，任务 1 写 `A`、任务 2 写 `B`，每写一个字母 `sleep(2)`。任务 B 先 `fork` 出任务 3，它写 `C`。一个睡下，另一个马上运行，所以第 6 行逐个轮流。它们只通过系统调用输出和等待，见上文“系统调用”和下文“用户态”。
- 两个任务共用输出位置。`task_write_char()` 写之前关中断、写完恢复原来的中断状态，保证“读位置、写字符、位置加一”不被切换打断。

两个顺序上的要求：

- **先发 EOI 再处理中断。** 切换发生在定时器处理函数里。任务 A 第一次运行时从 `task_main()` 的开头开始，不会回到那个处理函数；若 EOI 留到处理完才发，8259 就再也不会送来定时器中断，屏幕停在一个 `A` 上。中断门已清除 IF，提前发 EOI 也不会导致中断嵌套。Linux 0.11 的 `timer_interrupt` 同样一开始就发 EOI。
- **自检代码在开始调度之前运行。** 有的自检要让 `kmain()` 一直停在原地，开始调度后它只在任务 A、B 都睡着时才运行。

每次硬件任务切换都会置位 CR0 的 TS 位，此后第一次使用 x87/SSE 指令会触发 7 号异常。内核编译时用了 `-mgeneral-regs-only`，不会生成这类指令。

## 分页

`paging.c` 中的 `paging_init()` 建立两级页表，装入 CR3，再打开 CR0 的 PG 位。此后 CPU 访问的每个地址都是虚拟地址，要查表才能得到物理地址：

```text
虚拟地址 0xC0000004 = 1100000000 0000000000 000000000100
                       └ 高 10 位 ┘ └ 中 10 位 ┘ └ 低 12 位 ┘
                         768          0            4
CR3 → 页目录第 768 项 → alias_table → 第 0 项 → 物理页 0xB8000 → + 4 = 0xB8004
```

| 虚拟地址 | 物理地址 | 说明 |
| --- | --- | --- |
| `0x00000000`～`0x00000FFF` | 未映射 | 第 0 页，用来捕获空指针 |
| `0x00001000`～`0x00FFFFFF` | 与虚拟地址相同 | 前 16 MB 一一对应，4 张页表；其中只有 `.user` 段的页打开用户位，用户代码对用户态只读 |
| `0x40000000`～`0x403FFFFF` | 每个用户任务各自的 | 用户空间，1 张页表：exec 装入的程序在底部，栈从顶端往下长；没映射的页缺页时才分配，见下文“缺页处理”和“exec” |
| `0xC0000000`～`0xC0000FFF` | `0xB8000`～`0xB8FFF` | 显存的第二个地址，1 张页表 |
| 其余 | 未映射 | 访问会触发 14 号缺页异常 |

- 打开分页的那一刻，下一条指令的地址已经要经过页表翻译。前 16 MB 一一对应，所以代码、栈、显存和 GDT 的地址都不变，内核照常运行。Linux 0.11 的 `head.s` 同样一一对应地映射前 16 MB，不过它把页目录放在物理地址 0，我们放在 `.bss` 里。
- 页目录项和页表项的低 12 位是标志，这里用到存在位（1）、可写位（2）和用户位（4，见下文“用户态”）。存在位为 0 时访问该地址，CPU 产生 14 号缺页异常，把出错的虚拟地址放进 CR2，错误码的第 0 位表示页是否存在、第 1 位表示是不是写操作。异常面板的最后一行显示 CR2。
- 第 0 页不映射后，`*(int *)0 = 1` 这样的空指针写入会立即触发缺页，而不是悄悄改写物理地址 0。
- 写 `0xC0000000` 和写 `0xB8000` 改的是同一块显存。第 0 行的 `V` 就是 `kmain()` 通过 `0xC0000000` 写进去的。

## 物理页分配

`mem.c` 管理 1 MB～16 MB 之间的物理内存，做法与 Linux 0.11 的 `mm/memory.c` 相同：一个字节数组 `mem_map` 记录每个 4 KB 页被引用了几次，0 表示空闲，共 3840 项。

- `get_free_page()` 从 `mem_map` 的末尾往前找第一个 0，把它改成 1，把那一页清零后返回它的物理地址；一页都没有时返回 0（0 永远不是能分配的页）。所以第一次分到的是 16 MB 下面的 `0xFFF000`。Linux 0.11 用 `std; repne scasb` 从末尾往前扫，清零用 `rep stosl`。
- 交出去之前必须清零：页里可能还留着上一个使用者的数据，不清零就会被下一个使用者读到。分配器按物理地址直接写这一页，所以能分配的页都必须在一一对应映射的前 16 MB 内，`paging.c` 里有一条编译期断言保证这一点。
- `free_page(addr)` 把引用次数减一，减到 0 就回到空闲。释放一个本来就空闲的页说明内核自己记错了，调用 `panic()` 在第 19 行显示 `Kernel panic: …` 并停机，与 Linux 0.11 的 `free_page()` 一样。1 MB 以下的地址直接忽略：那是内核自己的代码、数据和显存，不归分配器管。
- 记引用次数而不是只记“用了没用”，是为以后 `fork` 时父子进程共用同一页（写时复制）准备的。
- 1 MB 以下不参与分配：内核的代码、`.bss`（页表、栈、TSS）都在 `0x10000`～`0x20000` 以内，显存和 BIOS 在 640 KB～1 MB。内存大小假定为 16 MB：Makefile 给 QEMU 的是 `-m 16M`，分页也只映射了前 16 MB；Linux 0.11 的 `main()` 同样把超过 16 MB 的内存截掉。Linux 0.11 还把 1 MB～4 MB 留作磁盘缓冲区，主内存从 4 MB 开始；这里还没有磁盘缓冲区，全部用来分配。
- 分配和释放都会刷新第 3 行。查找和标记之间关中断：否则两个任务可能在中间被切换，拿到同一页。

## 缺页处理

用户空间是虚拟地址 `0x40000000`～`0x403FFFFF` 这 4 MB（第 256 个页目录项），在每个用户任务自己的页目录里，各有各的一份。exec 把程序放在它的底部，栈从顶端往下长。任务 B 运行的是内核映像里的 `user_main()`，用户空间里开机时一页也没有映射，栈也不预先分配。TSS 里的 ESP 是 `0x40400000`，B 的第一条指令就往栈上压寄存器，CPU 查页表发现第 256 个页目录项不存在，触发 14 号缺页异常，错误码 6（页不存在、写、来自用户态），CR2 是出错的地址。

```text
任务 B：user_main 的第一条指令 pushl %ebp，ESP = 0x40400000
  └▶ #PF，CR2 = 0x403FFFFC，错误码 6
       interrupt_dispatch() → handle_page_fault(CR2, 错误码)
         页不存在？地址在用户空间？都是，那就补：
           当前页目录（CR3）的第 256 项是空的 → get_free_page() 分一页当页表
           get_free_page() 再分一页清零的物理页，填进页表：存在、可写、用户
       iretd 回到那条 pushl，CPU 重新执行，这次查表成功
```

- `handle_page_fault()` 只补两种条件同时满足的缺页：错误码第 0 位为 0（页不存在，而不是页存在但没权限），而且出错地址在用户空间内。写只读的代码页、碰内核的页（页存在但没有用户位）、读写堆和栈之间还没要过的地方（见下文“堆”），都不补，照原来的规则处理：用户程序出错就结束它，内核出错就显示异常面板。不检查范围的话，空指针、野指针都会被悄悄“补”上一页，再也发现不了。
- 内核也可能碰到没映射的页：用户把栈上一块还没用过的缓冲区交给 `write`。系统调用在碰它之前，就由 `prepare_user()` 调用 `handle_page_fault()` 把它补上（见上文“用户态”）；万一内核在特权级 0 真的缺页了，`handle_page_fault()` 同样会补。它不会在内核的页目录里建用户空间：任务 0 和内核任务 A 没有用户空间。
- 映射一页不用刷新 TLB：CPU 不缓存“不存在”的页表项，重新执行那条指令时会重新查表。
- 任务 B 结束（`exit` 或者被异常结束）时，`sched_exit()` 调用 `free_page_dir()`：把栈区页表里每一个存在的页还给分配器，再还掉页表和页目录本身，最后还掉内核栈。此刻 CPU 还在用这个页目录和内核栈，但中断关着，切走之前没有人会分配内存，这几页的内容不会被改掉；切换时 CPU 把寄存器存进静态的 `tss` 数组，换 CR3 也让 TLB 里的旧翻译作废。第 3 行随之回到 3839 页空闲。
- 栈区是用户空间顶端的 64 KB（`STACK_RESERVE`）。栈用超了，就伸进了堆和栈之间的空地，触发普通的缺页，进程被结束；`0x3FFFFFFF` 更是在用户空间以外。没有空闲页时也补不上，同样按出错处理。
- 第一次补上缺页时，内核在第 0 行第 9 列写入 `F`；第 3 行的 `page faults` 是补上的次数。正常运行时 B 只用到栈顶的一页，所以是 1。

Linux 0.11 的 `mm/page.s` 根据错误码的第 0 位把缺页分给两个函数：页不存在交给 `do_no_page()`，页存在但写了只读页交给 `do_wp_page()`（写时复制）。`do_no_page()` 用 `get_free_page()` 分一页、`put_page()` 填进页表，页表不存在时 `put_page()` 也先分一页当页表，与这里相同；它还会先试着与正在运行同一个程序的进程共用那一页，或者从可执行文件里把那一页读进来，这里只有清零的页。进程的栈同样是用到才分配的：`execve()` 只把参数和环境变量放进栈顶的几页，其余的栈页都在缺页时补上。进程结束时，`do_exit()` 调用 `free_page_tables()` 收回它的页。

## fork 与写时复制

任务 B 一开始就调用 `fork()`，复制出任务 3。父子进程都从 `fork()` 返回，接着往下走：父进程得到 3，写 `B`；子进程得到 0，写 `C`。第 6 行于是变成 `ABCABC…`。

- `sched_fork()` 找一个空的任务槽，分一页当新任务的内核栈，用 `copy_page_dir()` 复制页目录，再填 TSS。TSS 直接用父进程进入系统调用时栈上保存的寄存器：EIP 是 `int 0x80` 的下一条指令，CS、SS、ESP 是用户态的，只把 EAX 改成 0。新任务第一次被调度时，硬件任务切换直接把它放回用户态，好像 `fork()` 刚返回 0。它的内核栈此刻是空的：它从没在内核里运行过。Linux 0.11 的 `copy_process()` 也是用栈上的寄存器填新进程的 TSS，再把 `eax` 设为 0。
- `copy_page_dir()` 不复制用户空间的页：子进程有自己的页目录和页表，页表项指向和父进程同样的物理页，两边的页表项都去掉可写位、打上写时复制的记号（页表项第 9 位，CPU 不用这一位，留给操作系统），物理页的引用次数加一。本来就只读的页（exec 装入的程序代码）不打记号。父进程自己的页表项被改成只读，TLB 里可能还缓存着可写的旧翻译，所以要重新装入 CR3。Linux 0.11 的 `copy_page_tables()` 做同样的事。
- 谁先写栈，谁就触发缺页：错误码 7（页存在、写、用户态）。`handle_page_fault()` 看到写的是用户空间里一个只读、打了写时复制记号的页，交给 `copy_on_write()`：没有记号的只读页（程序的代码）不处理，写它的程序被结束。引用次数大于 1，就分一页、复制内容、换成自己的，旧页的引用次数减一；只剩自己在用（另一方已经复制走了，或者已经结束），直接改回可写。改的是存在的页表项，也要刷新 TLB。第一次写时复制时，内核在第 0 行第 10 列写入 `W`；第 3 行的 `copy-on-write` 是处理的次数。Linux 0.11 的 `do_wp_page()` 和 `un_wp_page()` 也是这样。
- 正常运行时：fork 时父子共用 1 个栈页；父进程先写，复制一份；子进程后写，只剩它自己用，直接改回可写。所以写时复制 2 次，只多用了 1 页。第 3 行用掉的 9 页是：任务 A、B、C 的内核栈，B 和 C 各自的页目录和栈区页表，原来的栈页和复制出的一页。
- 内核替用户写用户内存时也可能碰上共享的只读页。`paging_init()` 打开了 CR0 的 WP 位，特权级 0 写只读页同样会触发缺页，走同一条写时复制的路。386 没有 WP 位，在特权级 0 不理会只读位，所以 Linux 0.11 在内核写用户内存之前先调用 `verify_area()` 预先处理写时复制；WP 是 486 加上的，QEMU 模拟的 CPU 有它。
- 用户代码那一页（内核映像里的 `.user`）本来就是只读的，父子直接共用，不用复制。

## exec

`execv(path, argv)` 把当前任务换成硬盘上的程序，在 `exec.c` 的 `do_exec()` 里完成，与 Linux 0.11 的 `fs/exec.c` 中的 `do_execve()` 对应：

1. 把路径和参数从用户内存复制进内核：马上要扔掉旧的地址空间，它们会跟着消失。最多 16 个参数、共 1 KB。
2. 用 `namei()` 找到文件，它必须是普通文件、有执行权限（`mkfs.py` 照搬构建时的权限：`/bin` 下的程序是 0755，`/hello.txt` 是 0644）。读 ELF 头，检查是 32 位、小端、x86 的可执行文件，入口在用户空间里；再读程序头。
3. `new_page_dir()` 建一份新的页目录。每个要装入的段（`PT_LOAD`）一页页放进去：`map_user_page()` 在新页目录里分一页清零的物理页，再按物理地址把文件里属于这一页的部分读进来；段比文件内容长的部分（`.bss`）保持为 0。代码段映射成只读，数据段可写。段必须落在用户空间里，顶端留出 64 KB 给栈。
4. 在栈顶那一页摆好参数，从上往下依次是：参数字符串、`argv[argc] = 0`、`argv[0..argc-1]`、`argv`、`argc`、一个假的返回地址 0。于是程序的入口 `_start(argc, argv)` 可以写成一个普通的 C 函数（`user/ulib.c`），直接调用 `main()`，用它的返回值 `exit()`。
5. 都成功了，才用 `sched_set_page_dir()` 换上新的页目录（记进任务表和 TSS，再装入 CR3），收回旧的；再改写栈上保存的现场：EIP 改成程序的入口，ESP 改成新栈顶，EFLAGS 改成 `0x202`，通用寄存器清零。系统调用返回时，`iret` 就落到新程序的第一条指令上，EAX 是系统调用的返回值 0。中途任何一步失败，就收回新页目录、返回 -1，旧程序原封不动。
6. 打开的文件不受影响，新程序接着用；第一次 exec 成功时，内核在第 0 行第 11 列写入 `E`。

**脚本**：文件开头是 `#!` 的，第 2 步发现它不是 ELF 而是脚本：第一行写着解释器的路径，后面可以跟一个参数（到行尾的整段算一个）。exec 改去装入解释器，参数重新排成：解释器的名字、那个参数（有的话）、脚本的路径、原来的 `argv[1]` 以后，所以 `#!/bin/sh` 开头的 `/tmp/s a b` 运行起来就是 `sh /tmp/s a b`。解释器自己不能又是脚本；`#!` 后面没有解释器、参数加起来超过 16 个，都返回 -1。ps 里显示的是脚本的名字。新建的文件权限是 0644，要先 `chmod 755` 才能直接运行。Linux 0.11 的 `do_execve()` 也是这样处理 `#!` 的（tytso 加的）。

Linux 0.11 读的是 a.out 格式，exec 时并不把程序读进内存：程序的页在缺页时才由 `do_no_page()` 从文件里读，正在运行同一个程序的另一个进程已经有这一页时直接共用。参数也放在栈顶的几页里，同样是改写栈上的 `eip` 和 `esp`，让系统调用“返回”到新程序。

### 用户程序

用户程序在 `user/` 下，每个是一个 C 文件，和 `user/ulib.c` 链接在一起：`ulib.c` 里有入口 `_start`、`strlen`、`strcmp`、`print` 等几个函数，系统调用的包装来自 `syscall.h`，与内核共用。`user/user.ld` 把程序链接到用户空间的底部 `0x40000000`，代码和只读数据在前，数据从下一个 4 KB 边界开始，这样代码页和数据页能分开映射。`make` 把它们编成 `build/user/名称.elf`，装进硬盘的 `/bin/`：

| 程序 | 作用 |
| --- | --- |
| `letter X` | 每 2 个 tick 写一个字母 X。开机时任务 3 exec 它，第 6 行的 C 就是它写的 |
| `hello 参数…` | 打印 `hello` 和参数 |
| `check` | 检查 exec 把自己装对了：`.data`、`.bss`、`argc`、`argv` |

`check.c` 里的全局变量都加了 `volatile`：否则 clang 看出它们从没被改过，直接把值算出来，`.data` 和 `.bss` 根本不会生成，也就测不到 exec 有没有装对。

## exit 与 waitpid

进程结束和被父进程收走是两步，与 Linux 0.11 相同：

- `sched_exit(status)`：先收回用户内存（用户空间的页、页表、页目录）。自己的子进程成了孤儿，父进程改成 0：没有人会再等它们，已经结束的当场收走，以后结束的也直接收走。Linux 0.11 把孤儿交给 init（任务 1），由 init 的 `wait` 收走；这里还没有 init。
- 有父进程的任务变成僵尸（`TASK_ZOMBIE`）：内核栈和任务槽留着，`status` 记在任务表里；父进程正在 `waitpid` 里睡着，就把它叫醒。没有父进程的（内核建的任务 A、B，以及孤儿），内核栈也当场还掉。此刻还在用这个内核栈，但中断关着，切走之前没有人会分配内存，这一页的内容不会被改掉。
- `waitpid(pid, &status, options)` 在任务表里找自己的子进程（`pid` 为 -1 时任意一个）。找到僵尸，就取走状态、释放它的内核栈和任务槽（`release()`），返回它的任务号；子进程都还在运行，就把自己标成 `TASK_WAITING` 切走，被叫醒后再找一遍；带 `WNOHANG` 时不等，返回 0；一个子进程都没有，返回 -1。查找和睡下之间关着中断，子进程不会恰好在这中间结束，叫醒不会落空。Linux 0.11 的 `sys_waitpid()` 也是这样一圈圈找，找不到就把自己设为 `TASK_INTERRUPTIBLE`，靠子进程结束时发来的 `SIGCHLD` 叫醒。
- 状态最后才写回 `status`，那时中断已经打开：它可能落在 fork 留下的只读页上，写的时候要走一次写时复制。`sys_waitpid()` 先用 `user_write_ok()` 检查并准备好这个地址：写时复制的页先复制好，程序的代码页不行。
- 状态的格式：`exit(code)` 留下 `code` 的低 8 位；被异常结束的是 0x100 加异常号，例如缺页是 `0x10E`。Linux 用 `(code & 0xFF) << 8` 和信号编号区分两者，这里简化了。

## 磁盘与内存布局

| 内容 | 磁盘镜像偏移 | 加载后的物理地址 | 谁负责加载 |
| --- | --- | --- | --- |
| 第一阶段 `boot.bin` | 0～511 | `0x7C00`～`0x7DFF` | BIOS |
| 第二阶段 `loader.bin`（含 GDT） | 512～1023 | `0x8000`～`0x81FF` | 第一阶段 |
| 内核 `kernel.bin`（`KERNEL_SECTORS` 个扇区） | 1024 起 | `0x10000` 起 | 第二阶段 |
| 其余空间 | 内核之后 | 不加载 | 无 |

loader 的栈从 `0x7C00` 向低地址增长；进入内核后改用 `.bss` 中的内核栈。这里的 `0x8000` 是本实验选择的地址。VGA 文本显存从 `0xB8000` 开始，每个字符格占 2 字节：低字节是字符，高字节是颜色属性。第 r 行第 c 列的地址是 `0xB8000 + (r × 80 + c) × 2`。

进入内核后，loader 所在的 `0x7C00`～`0x81FF` 就不再需要了：内核用 `gdt_init()` 换上了自己的 GDT，栈也换成了 `.bss` 中的内核栈。

CHS 的扇区号从 1 开始。镜像写入命令中的 `seek=1` 跳过一个 512 字节块，对应 CHS 的扇区 2；`seek=2` 对应扇区 3。

1.44 MB 软盘有 80 个柱面、2 个磁头，每条磁道 18 个扇区。BIOS 按 CHS（柱面、磁头、扇区）读盘，第二阶段把从 0 开始连续编号的 LBA 换算成 CHS：

```text
扇区 = LBA % 每道扇区数 + 1      （CHS 的扇区号从 1 开始）
磁头 = (LBA / 每道扇区数) % 磁头数
柱面 = (LBA / 每道扇区数) / 磁头数
```

例如 LBA 20 是柱面 0、磁头 1、扇区 3，LBA 36 是柱面 1、磁头 0、扇区 1。每道扇区数和磁头数来自 `AH=0x08` 的查询结果，而不是写死的常数；查询结果中每道扇区数为 0 时改用 18，磁头数用 16 位保存（最大磁头号 255 加 1 是 256），保证后面的除法不会除以零。读完内核后，loader 向端口 `0x3F2` 写 0 关掉软驱马达：接下来要关中断、重设 8253 和 8259，BIOS 原本靠定时器中断关马达的那段逻辑不会再运行。Linux 0.11 的 `bootsect.s` 用 `kill_motor` 做同样的事。每次只读一个 512 字节的扇区，目标地址又按 512 对齐，所以永远不会跨越 64 KB 边界，满足软驱 DMA 的要求。Linux 0.11 的 `bootsect.s` 一次读一整条磁道以加快速度，原理相同。

磁盘镜像共 1,474,560 字节，没有文件系统。`boot.bin` 和 `loader.bin` 各自恰好 512 字节；只有第一阶段需要 `55 AA` 引导签名。`kernel.bin` 按实际代码长度生成，最后一个扇区不满 512 字节时，第二阶段多读到的部分是镜像中的零。

## 内核扇区数

loader 要读多少个扇区，由 `Makefile` 在汇编 `loader.asm` 时按 `kernel.bin` 的实际大小算出：`KERNEL_SECTORS = (字节数 + 511) / 512`，通过 `-DKERNEL_SECTORS=…` 传入。所以 `loader.bin` 依赖 `kernel.bin`，内核一变，loader 也会重新汇编。直接运行 `nasm loader.asm` 而不传这个值，会报错终止。

内核最多 512 个扇区（256 KB，读到 `0x10000`～`0x4FFFF`），超过时汇编 `loader.asm` 会报错。`.bss` 不计入 `kernel.bin` 的大小，但它在内存中紧跟内核之后，不能覆盖其他正在使用的内存。

## GDT

loader 进入保护模式时用的是写在 `loader.bin` 里的 GDT。进入内核后，`gdt.c` 中的 `gdt_init()` 在 `.bss` 里建一份内容相同的新表，用 `lgdt` 装入，再用一次远跳转重新装载 CS、用 `mov` 重新装载其余段寄存器：段寄存器缓存着装入时读到的描述符，换表后不重新装载就仍在用旧描述符。选择子保持不变，所以 IDT 等处引用的 `0x08`、`0x10` 都不用改。新表有 26 项：第 6、7 项是用户段，第 9 项只在自检 `OTHER_SEGMENTS` 中使用，第 10～25 项是 16 个任务槽的 TSS，第 3～5、8 项空着；后加的项用 `gdt_set_entry()` 填写。Linux 0.11 的 `head.s` 也会重建 GDT，因为 `setup.s` 留下的那份在 `0x90000` 附近，之后会被覆盖。

| 选择子 | 描述符 | 含义 |
| --- | --- | --- |
| `0x00` | `0x0000000000000000` | 空描述符，CPU 规定第 0 项必须为空 |
| `0x08` | `0x00CF9A000000FFFF` | 代码段：基址 0，界限 4 GB，可执行可读，DPL 0，32 位 |
| `0x10` | `0x00CF92000000FFFF` | 数据段：基址 0，界限 4 GB，可读写，DPL 0 |
| `0x33` | `0x00CFFA000000FFFF` | 用户代码段（第 6 项）：与内核代码段相同，只是 DPL 为 3；选择子的 RPL 也是 3 |
| `0x3B` | `0x00CFF2000000FFFF` | 用户数据段（第 7 项），DPL 3 |
| `0x48` | 仅在自检内核中填写 | 第 9 项：自检 `OTHER_SEGMENTS` 用的基址 1 MB 的数据段 |
| `0x50` 起，每项加 8 | 由 `sched_init()` 填写 | 第 10～25 项：任务 0～15 的 TSS，基址为对应 TSS 的地址，界限 103，类型为 32 位可用 TSS |

选择子的低 3 位是 RPL 和 TI，所以第 n 项的选择子是 n × 8。两个段都是平坦段，保护模式下的偏移就等于物理地址，写 `[0xb8004]` 访问的就是物理地址 `0xB8004`，`jmp eax` 跳到的也就是物理地址 `0x10000`。C 代码中的指针值同样直接就是物理地址。

## 硬盘

`make` 生成 4 MB 的 `build/hd.img`，它是一个 Minix 文件系统，见下文“文件系统”。`make run` 和测试把它接在 QEMU 的主 IDE 通道上（主盘）。

`hd.c` 是 ATA 硬盘的驱动，用 PIO 方式一次读写一个 512 字节的扇区：

```text
任务调用 hd_read(lba, buf)                         硬盘
  关中断；别人在用硬盘就 sleep_on(&hd_wait) 排队
  写 0x1F6 = 0xE0 | LBA 高 4 位（主盘、LBA 寻址）
  写 0x1F2 = 1，0x1F3～0x1F5 = LBA 低 24 位
  写 0x1F7 = 0x20（READ SECTORS）  ──────────────▶  找扇区、读数据
  sleep_on(&hd_wait)：睡下，CPU 去运行别的任务
                                                   数据准备好，拉 IRQ14
  IRQ14 → hd_handle()：读 0x1F7 状态（也是在应答中断），
          rep insw 从 0x1F0 读 256 个字，wake_up(&hd_wait)
  醒来：done 为 1，返回 0
```

- 写扇区时发 WRITE SECTORS（`0x30`），硬盘先要数据、不发中断：轮询到状态的 DRQ 位后用 `rep outsw` 写进 256 个字，再睡下等它写完后的 IRQ14。
- `hd_init()` 在开机时用 IDENTIFY（`0xEC`）命令问出扇区数（第 60、61 个字）和型号（第 27～46 个字，每个字里两个字符的顺序是反的），显示在第 1 行，再打开 8259 上的 IRQ14。此时还是任务 0 在运行，不能睡，所以先在设备控制寄存器 `0x3F6` 里关掉硬盘的中断，用轮询等它回答。IRQ14 在从片上，打开它还要打开主片上接从片的 IRQ2。
- 一次只处理一个请求：`busy` 为 1 时后来的任务排队，用完的任务 `wake_up` 叫醒它们。Linux 0.11 的 `kernel/blk_drv/` 有请求队列和电梯算法，用 CHS 寻址，`hd_out()` 发命令，`read_intr()` 和 `write_intr()` 在中断里搬数据，`end_request()` 唤醒等待的进程，结构与这里相同。
- 等待队列 `struct wait_queue` 是一个位图，第 n 位为 1 表示任务 n 睡在上面。`sleep_on(q)` 把当前任务标成 `TASK_BLOCKED` 并切走，`wake_up(q)` 把睡在上面的任务都改回能运行，它们醒来后各自重新检查条件，所以总是写成 `while (条件不满足) sleep_on(&q);`。调用 `sleep_on` 之前要关中断：否则检查完条件、还没睡下时中断恰好来了，`wake_up` 就落空了。任务 0 不能睡，它睡了，没事做的时候 CPU 无处可去。Linux 0.11 的 `sleep_on()` 用每个睡眠者栈上的 `tmp` 变量把它们串成一条链，这里任务最多 16 个，用一个位图更简单。
- 中断处理函数叫醒任务时，CPU 多半正停在任务 0 的 `hlt` 上。`interrupt_dispatch()` 处理完键盘、硬盘这些外设中断后调用 `sched_idle_wakeup()`：此刻是任务 0 在运行，就马上切到能运行的任务。不这样做的话，被叫醒的任务要等下一个定时器中断，每读一个扇区就要多等最多 10 毫秒，读 64 个扇区要半秒多。Linux 0.11 的任务 0 不停地调用 `pause()`，在 `schedule()` 里转圈，同样能马上切过去。

## 文件系统

硬盘上是一个 Minix v1 文件系统，格式与 Linux 0.11 用的相同（`include/linux/fs.h`），能读也能写。`make` 把仓库里的 `rootfs/` 复制到 `build/rootfs/`，用 `tools/mkbig.py` 加一个 600 KB 的测试文件 `/big`，再用 `tools/mkfs.py` 打包成 `build/hd.img`：

```text
块 0       引导块：只有一行说明文字
块 1       超级块：i 节点数 128、总块数 4096、两张位图各几块、第一个数据块、魔数 0x137F
块 2       i 节点位图          块 3       区块位图
块 4～7    i 节点表：128 个 i 节点，每个 32 字节
块 8 起    数据块：文件内容、目录内容、间接块
```

每块 1024 字节，是 2 个扇区。i 节点从 1 开始编号，1 号是根目录。i 节点里有文件类型和权限、大小、9 个块号：前 7 个直接指向数据块；第 8 个指向一个间接块，里面是 512 个块号；第 9 个指向二级间接块，里面是 512 个间接块的块号。所以 7 KB 以内的文件只用直接块，519 KB 以内再加一个间接块，`/big` 有 600 KB，要用到二级间接块。目录也是文件，内容是一条条 16 字节的目录项：2 字节的 i 节点号加 14 字节的文件名，每个目录的头两项是 `.` 和 `..`。

- **缓冲区缓存**（`buffer.c`）：`bread(block)` 返回一个装着那一块的缓冲区，用完调用 `brelse()`。缓冲区里已经有这一块就直接给出去；没有就挑一个没人在用、最久没用过的缓冲区，从硬盘读进来。别的任务正在读同一块，或者 16 个缓冲区全都有人在用，就睡下等。目录、i 节点表这些反复要查的块因此只读一次。新分配的块用 `bget()` 拿缓冲区，内容清零，不必先读。Linux 0.11 的 `fs/buffer.c` 用散列表和空闲链表管理几百个缓冲区，这里只有 16 个，按块号挨个找。
- **延迟写回**：改了缓冲区里的内容，调用 `bdirty()` 把它标成“脏”的，并不马上写盘：同一块（位图、i 节点表、目录）连着改好几次，最后只写一次。脏块在两种时候写回：缓冲区要换成别的块时，先挑干净的，全是脏的才挑一个脏的，先写回再换；`sync` 系统调用把所有脏块写回。init 每隔大约 5 秒调用一次 sync，所以突然关机最多丢掉最近几秒的修改。`df` 的第二行显示现在有几块是脏的、开机以来写回了多少块。Linux 0.11 也是这样：`b_dirt` 标脏，`getblk()` 换块时尽量挑不脏的，`sys_sync()` 写回所有脏块，用户态的 update 进程每 30 秒调用一次 sync。
- **挂载**（`fs_mount()`）：第一次用到文件系统时读超级块，检查魔数，在第 1 行显示大小。读硬盘要睡，所以只能在任务里做。Linux 0.11 由 init 进程调用 `setup` 系统调用，再由 `mount_root()` 读根文件系统的超级块。
- **读文件**（`inode_read()`）：按位置算出是文件的第几块，`bmap()` 换算成磁盘上的块号（直接块、间接块、二级间接块三段），`bread()` 读进来，复制出需要的部分。目标可以是用户的缓冲区：复制时可能缺页或写时复制，由缺页异常处理。
- **按路径找文件**（`namei()`）：从根目录起，把路径按 `/` 切成一段段，在目录里逐条比较目录项的名字，找到下一级的 i 节点号，再读出那个 i 节点。它只认 `/` 开头的绝对路径，相对路径在系统调用那一层先接上当前目录，见下文“当前目录”。
- **打开的文件**（`file.c`）：`open` 在文件表（32 项）里占一项，记下打开方式、i 节点和读写位置，再把任务的文件描述符表（8 项）中最小的空位指向它。fork 之后父子的描述符指向同一项，读写位置也共用，这是 Unix 的规矩：父进程先读掉的部分，子进程接着往后读。第 6 行的任务输出区也是一个“文件”，开机时内核把它放在任务 0、A、B 的 1 号描述符上，`write(1, …)` 就写到那里。任务结束时关闭所有描述符。Linux 0.11 的 `file_table[NR_FILE]` 和 `current->filp[NR_OPEN]` 也是这样两层。 每个任务还有一个 close-on-exec 位图（`fcntl(F_SETFD)` 设），exec 成功以后关掉这些描述符：不能在 `do_exec()` 里关，那时拿着文件系统锁，而关掉最后一个引用要 `iput()`，又要拿这把锁。`dup2(old, new)` 先关掉 `new`，再让它指向 `old` 的文件；Linux 0.11 的 `sys_dup2()` 在 `old` 和 `new` 一样时会把它关掉再返回出错，这里照 POSIX 什么也不做。
- **用户给的路径**：`sys_open()` 先把路径一个字节一个字节地复制进内核，每个字节都要在用户的内存里，不是 `/` 开头的接在当前目录后面，连起来最长 127 个字节，再交给文件系统。`read` 的缓冲区要用户可写，`user_write_ok()` 检查。

### 写文件

- **内存里的 i 节点表**（`iget()`、`iput()`，32 项）：同一个文件打开几次，共用表里的一项，大小和块号才不会各看各的：从一个描述符写进去，另一个马上读得到。i 节点改了就马上写进 i 节点表所在的那个缓冲区，跟着它写回硬盘。`iput()` 放下最后一个引用时，要是链接数已经是 0（文件删了），才收回它的块和 i 节点。Linux 0.11 的 `inode_table[NR_INODE]` 也是这样。
- **位图**：i 节点位图和区块位图里的每一位表示一个 i 节点或数据块用了没有。分配就是找一个 0 改成 1、把位图那一块标脏（`alloc_bit()`）；新分到的数据块先清零。区块位图的第 k 位对应第 `firstdatazone + k - 1` 块。Linux 0.11 的 `fs/bitmap.c` 里是 `new_block()`、`new_inode()`。
- **写**（`inode_write()`）：按位置算出文件的第几块，`bmap_create()` 和 `bmap()` 一样分三段换算，没有的块就分配，需要的间接块、二级间接块也一起分配。写过文件末尾，文件就变长。磁盘满了，写进去多少算多少，一个字节都写不进去返回 -1。
- **清空、删除**：`O_TRUNC` 和收回已删的文件都调用 `truncate_inode()`：放掉 7 个直接块、间接块里的块和间接块本身、二级间接块下的两层，长度变成 0。
- **硬链接**（`fs_link()`）：目录里的一项只是“名字 → i 节点号”，所以一个文件可以有好几个名字：`link` 在目录里再加一项，指向同一个 i 节点，链接数加一。从哪个名字打开都是同一个文件；删掉一个名字（`unlink` 的意思就是去掉一个链接）只是链接数减一，减到 0、也没人开着，才真正收回。目录不能链接，免得目录树里出现环。链接数在 Minix v1 的 i 节点里只占一个字节，所以最多 250 个名字（`LINK_MAX`，后来 Linux 的 minix 驱动也是 250）：不查的话第 256 个名字让它回绕成 0，文件在还有 255 个名字指着时就被收回了，i 节点再分给新文件，从旧名字读到的是别人的内容。Linux 0.11 的 `sys_link()` 就没有查。`mkdir` 同样要查父目录的链接数（每个子目录的 `..` 都算一个）。`mv` 就是先 `link` 新名字、再 `unlink` 旧名字，文件的内容一个字节也不用搬；目录搬不了，那还得改它的 `..`，要 `rename` 才行。这不是一步完成的：已经删掉了原来的新名字，`link` 却失败了，新名字就没了。Linux 0.11 的 `sys_link()` 相同，它也没有 rename。
- **目录**：新建文件时，先确认所在目录里没有同名的，分一个 i 节点，再在目录里加一项：先找空项（i 节点号为 0），没有就接在目录末尾。删除就是把那一项的 i 节点号清 0，i 节点的链接数减一。文件还开着也可以删：目录里看不见了，开着它的程序还能接着读写，最后一个关掉时才真正收回。`mkdir` 新建的目录里先放 `.` 和 `..`，链接数是 2，父目录的链接数加一（多了一个 `..` 指向它）；`rmdir` 只删空目录。路径末尾的 `/` 说的是目录：`/hello.txt/` 查不到，`open("/tmp/a/", O_CREAT)` 不会建出普通文件 `a`，`ln f d/`、`rm f/` 都不行，`mkdir /tmp/d/` 可以。读目录出错时，查找新名字不当作“没找到”，免得在目录里加出两个同名的项。Linux 0.11 的 `fs/namei.c` 里是 `add_entry()`、`sys_mkdir()`、`sys_rmdir()`、`sys_unlink()`。
- **文件系统锁**（`fs_lock()`）：读写硬盘会睡，两个任务同时改文件系统可能分到同一块，或者一个在读目录、另一个正改到一半。所以所有会改文件系统的操作，以及读文件、查路径、exec 装入程序，都先拿到这把锁，同时只让一个任务在里面。Linux 0.11 给每个 i 节点、每个缓冲区各加一把锁，并发更好，道理相同。
- **结束任务时**：`sched_exit()` 先关闭所有打开的文件，再关中断收回内存。最后一个关掉已经删了的文件时要收回它的块，要读写硬盘、会睡，必须趁内核栈和页目录都还在的时候做。

`make run` 不给硬盘加 `snapshot=on`，在 QEMU 里写的文件会留在 `build/hd.img` 里，下次运行还在（关 QEMU 之前运行 `sync`，或者写完等上 5 秒，让 init 写回脏块），直到 `rootfs/` 或用户程序改动、`make` 重新生成镜像。测试都带 `snapshot=on`，每次都从原样的镜像开始。

### 当前目录

每个任务记着自己的当前目录（`struct task` 的 `cwd`），是一个规范化过的绝对路径：内核建的任务是 `/`，fork 出的子进程照抄父进程的。

- **相对路径**：`open`、`stat`、`execv`、`unlink`、`mkdir`、`rmdir`、`chdir` 拿到的路径不是 `/` 开头的，`get_path()` 把它接在当前目录后面，再交给文件系统。路径里的 `.` 和 `..` 不用特别处理：它们本来就是每个目录里的两项，`namei()` 照常查下去，`/etc/..` 查到的就是根目录（根目录的 `..` 指向自己）。
- **`chdir`**：先确认路径存在而且是目录，再按字面去掉多余的 `/`、`.` 和 `..`（`normalize()`），存进 `cwd`：`cd /bin/../etc/./` 之后 `pwd` 打印 `/etc`。没有符号链接，按字面去掉 `..` 和真的往上走一级是一回事。
- **`getcwd`**：把 `cwd` 复制给用户。
- **`cd` 必须是 shell 的内建命令**：要是 fork 一个子进程去 `chdir`，换的是子进程的当前目录，子进程一结束就没了，shell 自己的不变。反过来，shell `cd` 之后再运行的程序都是它 fork 出来的，继承它的当前目录，所以 `pwd` 这个独立的程序打印的就是 shell 的当前目录。
- **与 Linux 0.11 的不同**：Linux 0.11 的 `current->pwd` 是当前目录的 i 节点（引用着它），`namei()` 遇到不以 `/` 开头的路径就从这个 i 节点查起；没有 `getcwd` 系统调用，`pwd` 要沿着 `..` 一级级往上，在上一级目录里找自己的名字。这里记的是路径，`getcwd` 直接复制就行；代价是当前目录可以被 `rmdir` 掉，之后的相对路径什么也找不到，而 Linux 0.11 的 `rmdir` 看到 i 节点还有别人引用（`i_count > 1`）就不删。

## 终端与 shell

### 终端

`tty.c` 是终端，与 Linux 0.11 的 `kernel/chr_drv/tty_io.c` 对应。键盘中断把扫描码翻译成字符后交给 `tty_input()`，这里按“规范模式”处理：

- 普通字符放进正在编辑的这一行（最多 127 个字符），同时回显在屏幕上；
- 退格删掉这一行的最后一个字符，屏幕上也擦掉，这一行删空了就不能再删：删不到提示符这些程序输出的东西。一行超过屏幕宽度会折到下一行，退格能跨回上一行；
- 回车把这一行连同换行符放进 `ready` 缓冲区（512 字节的环形缓冲区），叫醒睡在 `tty_wait` 上的任务；
- Ctrl+D 把这一行（不带换行）交出去，后面跟一个结束标记。这一行是空的，读的程序就得到 0，知道输入结束了：直接运行 `cat` 或 `wc`，敲几行，再按 Ctrl+D。键盘驱动记着左 Ctrl 是否按住，按住时字母变成控制字符，Ctrl+D 是 `0x04`。

`read()` 从控制台读时，`ready` 里没有敲完的行就睡下等；有，就读走一行（最多 `count` 个字节）。先在关中断时搬进内核的临时缓冲区，开中断后再复制给用户：复制时可能缺页或写时复制。`write()` 写到控制台时，逐个字符交给 `vga_putc()`，每个字符关一下中断，免得和键盘中断里的回显同时移动光标。Linux 0.11 的终端有三个队列：`read_q` 存键盘送来的原始字符，`copy_to_cooked()` 处理退格和回显后放进 `secondary`，`tty_read()` 从 `secondary` 里读；这里把前两步合在键盘中断里做。

### 设备文件

程序通过文件找到终端：`make` 让 `mkfs.py` 在镜像里建两个字符设备文件 `/dev/tty0`（设备号 4,0）和 `/dev/tty1`（4,1）。设备文件没有内容，i 节点的类型是字符设备（`0020000`），第一个区块号存的是设备号，与 Linux 0.11 相同。`open()` 打开字符设备时，按设备号把打开的文件标成控制台或第 6 行，之后的 `read`、`write` 交给终端或第 6 行。macOS 上普通用户建不了设备文件，所以它们不放在 `rootfs/` 里，由 `mkfs.py --chr` 直接写进镜像。

### init 和 shell

init（任务 B，内核映像里的 `user_main()`）先 fork 出写 C 的 `/bin/letter`，再拉起 shell：子进程关掉继承来的 1 号描述符（第 6 行），把 `/dev/tty0` 打开三次，正好得到 0、1、2 号描述符，再 exec `/bin/sh`。之后 init 一边写 B，一边用 `waitpid(-1, 0, WNOHANG)` 收走结束了的子进程，shell 退出了就再拉起一个；shell 一下子就退出了（比如没有硬盘），就隔 1 秒再试，免得一刻不停地 fork。写 C 的子进程 exec 失败时，用内核映像里的代码接着写 C，不会往下走去拉起第二个 shell。Linux 0.11 的 `init()` 也是打开 `/dev/tty0`、`dup` 两次，再 fork 出 `/bin/sh`，在循环里 `wait` 并重新拉起它。自检内核不拉起 shell：它们要用控制台窗口检查键盘回显。

`user/sh.c` 是一个很小的 shell：打印 `$ `，`read(0)` 读一行，按空格切成参数，命令名里没有 `/` 的到 `/bin` 下找；fork 一个子进程去 exec，`waitpid` 等它结束，被异常结束的报告异常号。用 `|` 隔开的几段，每段一个子进程，相邻两段之间一个管道，见下文“管道”。每一段还可以带 `> 文件`（清空后写）、`>> 文件`（接在末尾写）、`< 文件`（从文件读标准输入）：还有 `2> 文件`、`2>> 文件`（标准错误写进文件）和 `2>&1`（标准错误也接到标准输出那里）。子进程在 exec 之前打开那个文件，用 `dup2` 接到 0、1 或 2 号描述符上。程序出错的消息都写到标准错误（`eprint()`），所以 `nosuch | wc` 里 wc 读到的是空的，消息直接出现在屏幕上；`cat /nothing 2>&1 | wc` 才把它也送进管道。在空行上按 Ctrl+D 和 `exit` 一样退出。`sh 脚本` 从文件里一行行读命令来执行，不打提示符，`#` 开头的行是注释，读完就退出；运行脚本的 sh 不接住 Ctrl+C，它和它正在运行的程序一起被结束。最后一个参数是 `&` 的在后台运行，不等它，每次读命令之前收走已经结束的后台程序。内建命令有 `cd`（不带参数回到 `/`，为什么必须内建见上文“当前目录”）、`exit` 和 `help`。

| 命令 | 作用 |
| --- | --- |
| `ls [-l] [目录]` | 直接 `read` 目录文件（不给就是当前目录），一条条解析 16 字节的目录项，再用 `stat` 问出每一项的类型和大小；`-l` 换成长格式：类型和权限（rwx 各三位）、链接数、主人、组、大小、修改时间（UTC） |
| `pwd` | 用 `getcwd` 取当前目录，打印出来 |
| `date` | 打印现在的时间（UTC） |
| `touch 文件…` | 文件不存在就新建一个空的，存在就把修改时间改成现在 |
| `cat [文件…]` | 把文件内容写到标准输出；没有给文件就读标准输入 |
| `rm 文件…`、`mkdir 目录…`、`rmdir 目录…` | 删文件、建目录、删空目录 |
| `ln 文件 新名字` | 给文件再起一个名字，两个名字的 i 节点号一样 |
| `mv 文件 新名字`、`mv 文件 目录` | 改名或搬进目录：link 新名字再 unlink 旧名字；新名字是个文件就先删掉它；目录搬不了 |
| `chmod 权限 文件…` | 用八进制改权限，比如 `chmod 755 脚本` |
| `sh [脚本]` | 不给参数是交互的 shell；给了脚本就从文件里读命令 |
| `df` | 用 `fsinfo` 问出数据块和 i 节点各用了多少，以及缓冲区缓存里有几块是脏的 |
| `sync` | 把脏块都写回硬盘 |
| `wc [文件…]` | 数行数、词数和字节数；没有给文件就读标准输入，读到 0 为止 |

| `ps` | 用 `taskinfo` 逐个问 16 个任务槽，列出任务号、父进程、状态（R 能运行、S 在 sleep 里、Z 僵尸、W 在 waitpid 里、B 在等待队列上）和名字。名字是内核起的（idle、task_a、init），exec 之后是程序的文件名 |

每个程序结束时，内核照旧在第 7 行写出 `task N exited with code M`。

### 管道

`pipe(fd)` 建一个管道（`pipe.c`）：缓冲区是从分配器拿来的一页，当作环形缓冲区用；文件表里占两项，一项是读的一头，一项是写的一头，分别放进最小的两个空闲描述符。与 Linux 0.11 的 `fs/pipe.c` 相同：

- 读：管道空着、还有人拿着写的一头，就睡下等；有数据就读走，最多读到要的字节数，不等凑满。管道空了、写的一头全都关了，返回 0：读的一方由此知道数据到头了。
- 写：管道满了、还有人拿着读的一头，就睡下等；读的一头全都关了，再写也没人看：给写的进程发 SIGPIPE，默认就结束它，忽略了 SIGPIPE 的才看到 write 返回 -1，和 Linux 0.11 的 `write_pipe()` 相同。
- 读写双方睡在同一个等待队列上，每读走或写进一些数据都叫醒对方。和用户内存之间的复制在开中断时做，每次最多 512 字节：复制时可能缺页。
- 每一头被几个打开的文件拿着，记在 `readers`、`writers` 里。一头的最后一个描述符关掉时（`file_put()` 里引用次数减到 0），计数减一，叫醒另一头；两头都关了，还掉缓冲区那一页。fork 会给每个打开的文件加一个引用，所以管道多余的描述符必须关掉：只要还有一个进程拿着写的一头，读的一方就永远等不到 0。

shell 运行 `ls /bin | grep e | wc` 时，先建第一个管道，fork 出 ls：它 `close(1); dup(写的一头)`，`dup` 返回最小的空闲描述符，正是刚关掉的 1 号，于是 ls 的标准输出就成了管道，再关掉两头原来的描述符，exec ls。grep 的标准输入接上一个管道读的一头，标准输出接下一个管道写的一头；wc 只接标准输入。shell 自己每建一个子进程就关掉它不再需要的那一头，最后等所有子进程结束。Linux 0.11 上运行的 shell 也是这样，用 `pipe`、`fork`、`dup` 拼出管道。

## 信号

信号是内核通知进程“出了某件事”的办法：按了 Ctrl+C、别的进程用 `kill` 叫它结束、往没人读的管道里写。每个任务记着收到、还没处理的信号（`struct task` 的 `signal`，第 sig − 1 位）和每个信号的处理方式（`action[]`：默认、忽略，或者用户的处理函数）。编号与 Linux 0.11 相同：SIGINT 2、SIGKILL 9、SIGPIPE 13、SIGALRM 14、SIGTERM 15。

- **发信号**（`sched_kill()`）：`kill(pid, sig)` 的 `pid` 大于 0 发给那个任务，为 0 发给自己所在的进程组（自己也收到），小于 -1 发给 `-pid` 那一组。目标忽略这个信号，就直接丢掉；SIGKILL 不能忽略。任务 0、A 和 init 收不到信号：前两个是内核任务，从不回到用户态，信号永远处理不了；init 要收养孤儿、拉起 shell，不能结束。
- **什么时候处理**：从用户态进来的中断（系统调用、定时器、键盘……）处理完、回到用户态之前，`interrupt_dispatch()` 取出编号最小的信号。没设处理函数的，默认动作是在第 7 行写出 `task N killed by signal S`，结束进程，留给父进程的状态是 0x200 加信号编号。Linux 0.11 在 `system_call.s` 的 `ret_from_sys_call` 里做同样的检查，再交给 `do_signal()`；没设处理函数的信号，默认动作就是 `do_exit()`。
- **处理函数**：`signal(sig, handler)` 设了处理函数的，内核让进程“先去调用它一下”：在用户栈上压 7 个字，从低地址往高依次是 `sig_restore` 的地址（处理函数的返回地址）、信号编号（处理函数的参数）、eax、ecx、edx、EFLAGS、原来要回去的 EIP，再把中断返回的 EIP 改成处理函数。iret 落到处理函数里，它是普通的 C 函数，返回时 ret 到 `sig_restore`；`sig_restore`（`user/ulib.c` 里的几行汇编）跳过信号编号，弹回 eax、ecx、edx、EFLAGS，再 ret 到原来的地方，程序接着往下走。eax 里是被打断的系统调用的返回值，所以 read 在处理函数运行之后返回 -EINTR；ebx、esi、edi、ebp 由处理函数自己按 C 的约定保存。进入处理函数时清掉 DF 和 TF：C 函数要求进来时 DF 是 0。这和 Linux 0.11 的 `do_signal()` 摆的一模一样，`sig_restore` 就是它 libc 里的 `__sig_restore`。不同的是 Linux 0.11 的 `signal()` 设的处理函数只管一次（`SA_ONESHOT`），这里一直有效。
- **睡着的任务**：睡在 sleep、waitpid、终端和管道上的任务，不知道要等多久，信号会把它叫醒（`send_signal()` 把它改回能运行），系统调用返回 -EINTR，回到用户态之前再处理信号：`cat` 等着敲字时，按 Ctrl+C 能马上结束它。等硬盘、等缓冲区、等文件系统锁很快就有结果，半途放弃还会留下改到一半的数据，所以不能被打断，信号要等它们做完。Linux 0.11 也分 `TASK_INTERRUPTIBLE` 和 `TASK_UNINTERRUPTIBLE` 两种睡眠。
- **闹钟**：`alarm(秒数)` 记下到期的 tick，定时器中断里 `wake_sleepers()` 查到闹钟到了，就给它发 SIGALRM，它要是正睡着也被叫醒；`pause()` 睡到来了一个信号为止。fork 出的子进程没有父进程的闹钟，exec 之后闹钟还在。`/bin/sleep` 就是用这两个写的：给 SIGALRM 设一个处理函数，定好闹钟，pause 等它，早年 Unix 的 C 库里的 `sleep()` 也是这样。Linux 0.11 的 `sys_alarm()`、`sys_pause()` 相同，`schedule()` 开头查闹钟；只是它返回的剩余秒数向下取整。
- **进程组和 Ctrl+C**：每个任务属于一个进程组（`pgrp`），fork 时继承。init 拉起 shell 时，子进程先 `setsid()` 自成一组，再打开 `/dev/tty0`：进程组的头第一次打开控制台，它就成了控制终端，这一组就成了终端的前台进程组；进程组的头结束时清掉。按 Ctrl+C，终端丢掉正在编辑的这一行，回显 `^C`，给前台进程组的每个任务发 SIGINT：shell 和它 fork 出的程序都在这一组，init 和写 C 的 letter 不在。Linux 0.11 的 `init()` 也是先 `setsid()` 再打开终端，`copy_to_cooked()` 遇到 Ctrl+C 就调用 `tty_intr()`；它不回显，也不丢掉这一行。
- **shell 怎么用**：shell 忽略 SIGTERM（`kill 0` 发给这一组，也不会把它自己结束），给 SIGINT 设了一个什么也不做的处理函数，作用只是打断它正睡着的系统调用：在提示符上按 Ctrl+C，read 返回 -EINTR，shell 重新打出提示符；前台程序运行时按，waitpid 返回 -EINTR，shell 接着等。fork 出的子进程在 exec 之前把 SIGTERM 改回默认，SIGINT 也改回默认（前台），就被 Ctrl+C 结束；或者改成忽略（`&` 的后台程序）。exec 换了程序，原来的处理函数没有意义了，改回默认；忽略的信号 exec 之后仍然忽略，所以 Ctrl+C 停不了后台程序，要用 `kill`。Linux 0.11 的 `do_execve()` 把 32 个信号的处理方式全改回默认，连忽略的也改回来；这里照 POSIX 的规定，忽略的保持忽略。shell 不报告被 SIGINT 和 SIGPIPE 结束的程序，被别的信号结束的报告 `sh: … killed by signal N`。

## 时间

开机时 `time_init()` 读一次 CMOS 里的实时时钟（端口 0x70 写寄存器号、0x71 读），换算成 1970 年 1 月 1 日 0 点（UTC）以来的秒数，记作开机时间；以后的“现在”就是开机时间加上 `timer_ticks / 100` 秒（`current_time()`）。QEMU 的时钟默认就是宿主机的 UTC 时间。

- **读 CMOS**：寄存器 0、2、4、7、8、9 是秒、分、时、日、月、年。时钟正在更新的那一刻（寄存器 A 的第 7 位）读出来可能对不上，就等它更新完；读完再读一遍秒，变了就重读。寄存器 B 的第 2 位说明数是二进制还是 BCD（QEMU 默认 BCD），第 1 位说明是 24 小时制还是 12 小时制。年份只有两位，世纪在寄存器 0x32。
- **换算**：`syscall.h` 里的 `date_to_unix()`、`unix_to_date()` 内核和用户程序共用。闰年要能被 4 整除，但被 100 整除的不是，被 400 整除的又是：2000 年是闰年，2100 年不是。32 位无符号的秒数能用到 2106 年 2 月 7 日。
- **文件时间**：Minix v1 的 i 节点里有一个修改时间。新建文件时是现在；`inode_write()` 写进东西时改成现在，目录里增删一项也是往目录文件里写，所以目录的修改时间跟着变；清空文件也算修改。`utime` 可以直接设，`touch` 用它。`mkfs.py` 打包时，普通文件取源文件的修改时间，目录和设备文件取打包的时刻。`stat` 返回修改时间和 i 节点里的主人、组。
- 第 4 行右边每秒刷新一次现在的时间。
- Linux 0.11 的 `time_init()` 也是读到秒数前后一致为止，`kernel_mktime()` 换算，`CURRENT_TIME` 是 `startup_time + jiffies / HZ`。不过它只认“每 4 年一个闰年”，年份也只用两位、一律当成 19xx：到了 2000 年就算错了，这就是千年虫。它写 CMOS 时用的是 `0x80 | 寄存器号`，顺便屏蔽了 NMI，这里不屏蔽。

## 堆：brk 和 malloc

程序事先不知道要多少内存时（`sort` 要把所有的行都读进来才能排序），就向内核要一块堆。用户空间从低往高依次是：程序（代码、数据、`.bss`）、堆、一段空地、顶端 64 KB 的栈区。堆最高也离栈区 16 KB（`BRK_LIMIT`），中间总留着空地。

- **brk**（`sched_brk()`）：每个任务记着堆的起点 `start_brk` 和末尾 `brk`。exec 把两者都设在程序最高的段的末尾，也就是 `.bss` 的末尾（链接脚本 `user/user.ld` 里的 `__end`）；最高的段是只读的（程序没有数据段）时，那一页剩下的地方写不了，堆从下一页开始；init 的代码在内核映像里，它的堆从 `0x40000000` 开始；fork 照抄。`brk(addr)` 把末尾挪到 `addr`：不能低于起点，最高到 `BRK_LIMIT`，做不到就不动；返回现在的末尾，所以 `brk(0)` 就是问“堆到哪儿了”。
- **用到才分配**：挪高 brk 并不分内存，缺页时 `handle_page_fault()` 才补。程序和堆（brk 所在的那一页也算）、栈区缺的页都补；堆和栈之间还没要过的地方不补，用到那里就是程序的错，它被缺页异常结束，系统调用的缓冲区在那里就返回 -1。栈用超了 64 KB，碰到的也是这段空地：进程被结束，而不是悄悄写进堆里。挪低 brk 也不收回已经补上的页，进程结束时一起收回。
- **malloc**（`user/ulib.c`）：`sbrk(n)` 把 brk 往上推 n 个字节，返回原来的末尾。`malloc` 把堆分成一块块，每块前面 8 个字节记着这一块多大、空着没有：从头找第一个够大的空块（路上把挨着的空块并成一块），大得多就切开；找不到就 sbrk 一块新的。`free` 把块标成空的，再和后面紧挨着的空块并成一块。`realloc` 遇到堆末尾的块，直接 sbrk 让它变大，不用搬。程序自己直接 sbrk 过的一段，malloc 记成一个占着的块跨过去。这是最简单的分配器，真正的 malloc 会按大小分桶、把空块串成链表、把堆末尾的空块还给内核。
- **sort** 把所有输入读进一块用 realloc 不断翻倍的缓冲区（它一直在堆末尾，原地变大），再把每一行的位置放进另一个不断翻倍的数组，用归并排序排好打印出来；一个文件的最后一行没有换行，就补一个，免得和下一个文件的第一行接在一起。`cat /big | sort | wc` 排 600 KB 时，第 3 行的空闲页一度少了 170 多页；排三份 /big（1.8 MB）少了 490 多页，sort 结束后又全回来了。
- Linux 0.11 的 `sys_brk()` 也只是记下这个数，允许的范围是代码的末尾到栈底往下 16 KB，页同样在缺页时由 `do_no_page()` 补上；不过它的 64 MB 用户空间里，数据段以上的地方缺页都补，不区分堆和栈。

## 修改实验

- 改 `boot.asm` 中的 `mov al, 'A'`：改变第一阶段输出。
- 改 `loader.asm` 中的 `mov al, 'B'`：改变第二阶段在实模式下的输出。
- 改 `loader.asm` 中的 `'P'` 或属性 `0x07`：改变保护模式下的输出和颜色，例如 `0x1F` 是蓝底白字。
- 改 `entry.asm` 中的 `'K'`：改变内核入口的输出。
- 改 `kernel.c` 中 `kmain()` 打印的字符串，或 `kernel.h` 中的 `VGA_GRAY`：改变 C 代码的输出。
- 若要观察 BIOS 读盘失败，将 `boot.asm` 中的 `mov cl, 2` 暂时改成 `mov cl, 0`。CHS 扇区 0 无效，重试 3 次后应看到 `AE`。实验后改回 2，关闭旧窗口并重新运行。
- 若要观察读内核失败，将 `loader.asm` 中 `read_sector` 里紧接着 `mov dh, dl` 的 `mov dl, [boot_drive]` 暂时改成 `mov dl, 0x81`（一块不存在的硬盘）。每次读都会失败，重试 3 次后应看到 `ABE`。实验后改回。
- 若要观察三重错误，将 `loader.asm` 中 `protected_mode` 后面的 `mov ax, DATA_SEL` 暂时改成 `mov ax, 0x18`。GDT 只有 3 项，`0x18` 超出界限，装入段寄存器时触发一般保护异常（13 号）；此时还没有 IDT，处理异常再次出错变成双重错误（8 号），最终三重错误。Makefile 带有 `-no-reboot`，QEMU 窗口会直接关闭。用 `make run QEMU_FLAGS="-d int,cpu_reset -D qemu.log"` 运行，可在 `qemu.log` 中看到 `new 0xd`、`new 0x8` 和 `Triple fault`。实验后改回。
- 若要观察忘记发 EOI 的后果，将 `interrupt.c` 中 `interrupt_dispatch()` 里的 `pic_send_eoi(vector);` 暂时注释掉。`ticks` 停在 1，键盘也没有反应：8259 一直等着 CPU 回复，不再送来定时器和优先级更低的键盘中断。实验后改回。
- 若要改变控制台窗口的位置和大小，修改 `kernel.c` 中的 `CONSOLE_TOP` 和 `CONSOLE_BOTTOM`。窗口不要覆盖第 0～6 行，否则滚动时会把这些固定内容一起移走。
- 若要观察抢占，运行 `make run BUILD=build/selftest/user_spin SELFTEST=USER_SPIN`。用户程序写一个 `s` 后一直空转、从不睡眠，任务 A 只能等它的时间片用完才运行，第 6 行约每 0.2 秒多一个 `A`，第 4 行的空闲比例为 0%。把 `sched.c` 中的 `TASK_SLICE` 改成 4，`A` 就快了 5 倍。正常构建中两个任务都睡得很勤，改 `TASK_SLICE` 看不出区别。
- 若要看用户栈按需增长，运行 `make run BUILD=build/selftest/user_deep_stack SELFTEST=USER_DEEP_STACK`。用户程序用掉 5 页栈后 `exit(3)`，第 3 行的 `page faults` 变多，任务结束后空闲页回到 3840。
- 若要看没有缺页处理会怎样，把 `interrupt.c` 中 `interrupt_dispatch()` 里调用 `handle_page_fault()` 的那个 `if` 整段注释掉。任务 B 执行第一条指令就被结束：第 7 行是 `task 2 killed by #PF page fault: … error=0x00000006`，第 0 行停在 `ABPKCVIT`（B 连第一个系统调用都没来得及做，所以也没有 `U`），第 6 行只剩 A。实验后改回。
- 若要对比睡眠时不让出 CPU 的样子，把 `sched.c` 中 `sched_sleep()` 末尾标记睡眠、切走的 5 行换成 `while (timer_ticks - start < ticks) __asm__ volatile("sti; hlt");`。第 6 行变回每段约 10 个字母，空闲比例变成 0%：CPU 一直被睡着的任务占着。实验后改回。
- 若要观察 EOI 发晚了的后果，把 `interrupt_dispatch()` 中的 `pic_send_eoi(vector);` 挪到处理函数之后。切到任务 A 后定时器就停了，第 6 行只有一个 `A`，键盘也没有反应。
- 若要改变时钟频率，修改 `kernel.h` 中的 `TIMER_HZ`。改成 50，`ticks` 每秒加 50。改成 1000 也能明显变快，但在 QEMU 的 TCG 模拟下会丢失部分中断，实测每秒只加约 700。不要小于 19，否则分频值超出 16 位。
- 若要亲眼看到除零异常，运行 `make run BUILD=build/selftest/divide_error SELFTEST=DIVIDE_ERROR`。异常面板会出现 `Exception 0 #DE divide error` 和出错指令的 `EIP`，用 `objdump -d build/selftest/divide_error/kernel.elf` 可以看到那个地址正是 `divl`。`selftest.c` 中用的是内联汇编：如果写成 C 的 `1 / zero`，clang 会把它优化成不用除法指令的比较，根本不会触发异常。
- 若要亲眼看到缺页异常，运行 `make run BUILD=build/selftest/unmapped SELFTEST=UNMAPPED`（读未映射的 `0xD0000000`）或 `make run BUILD=build/selftest/null_write SELFTEST=NULL_WRITE`（写空指针）。异常面板的第 2 行显示错误码，最后一行显示 CR2。
- 若要亲眼看到完整的寄存器面板，运行 `make run BUILD=build/selftest/register_dump SELFTEST=REGISTER_DUMP`。`selftest.c` 先把 EAX～EBP 设为 `0x11111111`～`0x77777777`，再执行 `ud2`。
- 若要看用户态程序越权，运行 `make run BUILD=build/selftest/user_write_kernel SELFTEST=USER_WRITE_KERNEL`（写内核变量 `timer_ticks`）或 `make run BUILD=build/selftest/user_privileged SELFTEST=USER_PRIVILEGED`（执行 `cli`）。第 7 行出现黄色的结束消息，任务 B 不再运行，第 6 行很快只剩 A；内核和任务 A 照常运行，不出现异常面板。
- 若要看用户程序正常退出，运行 `make run BUILD=build/selftest/user_exit SELFTEST=USER_EXIT`。用户程序写出 `bye` 后调用 `exit(7)`，第 7 行为 `task 2 exited with code 7`。
- 若要看内核拒绝用户传来的坏指针，运行 `make run BUILD=build/selftest/user_bad_pointer SELFTEST=USER_BAD_POINTER`。用户程序把内核地址交给 `write`，得到 -1 后写一个 `K`，第 6 行会出现一个 `K`。把 `syscall.c` 中 `sys_write()` 的 `user_range_ok()` 检查删掉再运行，`K` 就变成了 `X`，前面还多出一个内核代码的字节。
- 若要让任务 B 回到内核态，把 `sched.c` 中的 `init_user_task(2, …)` 改成 `init_task(2, task_main, cr3)`。第 6 行照常交替出现 A、B，但第 0 行不再出现 `U`。
- 若要换一个位置写 `V`，修改 `kernel.c` 中 `((volatile uint16_t *)VGA_ALIAS)[5]` 的下标，例如改成 `80 * 3`，`V` 就会出现在第 3 行行首。下标超过 2047（一页 4 KB 的范围）时会触发缺页，因为别名只映射了一页。
- 若要亲眼看到未填写的 IDT 表项被触发，运行 `make run BUILD=build/selftest/bad_gate SELFTEST=BAD_GATE`。`selftest.c` 执行 `int $0x30`，应看到 `Exception 13 #GP general protection`，`error=0x00000182`，即 `0x30 × 8 + 2`。

读取成功只表示扇区读取完成；这个最小实验尚未检查第二阶段和内核的内容或校验和。

`bits 16`、`bits 32` 和 `org` 是汇编指令，不是 CPU 执行的机器指令。`org` 告诉汇编器加载地址，不会在文件开头填充相应数量的字节。`loader.asm` 中远跳转之前按 16 位编码，`protected_mode` 之后按 32 位编码，与 CPU 当时所处的模式一致。`entry.asm` 和 `isr.asm` 编译成 ELF 目标文件，加载地址由链接脚本决定，所以不写 `org`。

## 文件

| 文件 | 作用 | 对应 Linux 0.11 |
| --- | --- | --- |
| `boot.asm` | 第一阶段：读盘、错误处理和跳转 | `boot/bootsect.s` |
| `loader.asm` | 第二阶段：打印 `B`，读入内核，建立 GDT、打开 A20、进入保护模式，打印 `P` 后跳进内核 | `boot/bootsect.s`、`boot/setup.s` |
| `entry.asm` | 内核入口 `_start`：设置内核栈、清零 `.bss`、打印 `K`，调用 `kmain()` | `boot/head.s` |
| `isr.asm` | 48 个中断入口和公共保存、恢复代码 | `kernel/asm.s`、`kernel/system_call.s` |
| `kernel.c` | `kmain()`：初始化各模块，打开中断 | `init/main.c` |
| `gdt.c` | 内核自己的 GDT | `boot/head.s` 中的 `setup_gdt` |
| `interrupt.c` | IDT、8259、中断分发、异常显示和 `panic()` | `kernel/traps.c`、`kernel/panic.c` |
| `paging.c` | 页目录和页表，打开分页，每个用户任务的页目录，缺页时补页，写时复制，任务结束时收回用户页 | `boot/head.s` 中的 `setup_paging`，`mm/memory.c` 中的 `do_no_page()`、`put_page()`、`copy_page_tables()`、`do_wp_page()`、`free_page_tables()` |
| `mem.c` | 物理页分配和引用计数：`mem_map`、`get_free_page()`、`free_page()` | `mm/memory.c` 中的同名函数和 `mem_init()` |
| `timer.c` | 8253 定时器，CMOS 实时时钟和现在的时间 | `kernel/sched.c` 中的 `sched_init()`、`do_timer()`，`init/main.c` 中的 `time_init()`，`kernel/mktime.c` |
| `syscall.c`、`syscall.h` | 系统调用：内核一侧的分发表，调用方使用的编号和包装函数 | `kernel/system_call.s`、`include/unistd.h` |
| `user.c` | 用户程序：任务 B 在用户态运行的 `user_main()`，它 `fork` 出任务 3 | 无（Linux 0.11 的用户程序是磁盘上的可执行文件） |
| `sched.c` | 任务表、TSS、硬件任务切换、睡眠与唤醒、等待队列、fork、exit、waitpid、信号和进程组、当前目录 | `kernel/sched.c` 中的 `schedule()`、`sleep_on()`，`kernel/fork.c` 中的 `copy_process()`，`kernel/exit.c` 中的 `do_exit()`、`sys_waitpid()`、`sys_kill()`，`kernel/signal.c`，`include/linux/sched.h` 中的 `switch_to` |
| `hd.c` | ATA 硬盘驱动：IDENTIFY、按 LBA 读写扇区、IRQ14 | `kernel/blk_drv/hd.c`、`ll_rw_blk.c` |
| `buffer.c` | 缓冲区缓存：`bread()`、`bget()`、`bdirty()`、`brelse()`，延迟写回和 `sync` | `fs/buffer.c` |
| `fs.c`、`fs.h` | Minix v1 文件系统：超级块、i 节点表、位图、`bmap()`、`namei()`、写文件、目录的增删、文件系统锁 | `fs/super.c`、`fs/inode.c`、`fs/namei.c`、`fs/bitmap.c`、`fs/truncate.c`、`include/linux/fs.h` |
| `file.c` | 打开的文件、文件表 | `fs/open.c`、`fs/read_write.c`、`fs/file_dev.c`、`fs/file_table.c` |
| `exec.c` | exec：读 ELF 文件，建新的地址空间，摆好参数 | `fs/exec.c` |
| `user/` | 用户程序和它们的小函数库（系统调用、malloc、信号处理函数的返回）、链接脚本 | 无（Linux 0.11 的程序用 libc 编译） |
| `rootfs/` | 硬盘上文件系统的内容，`/bin` 由 `make` 放进去 | 无 |
| `tools/mkfs.py` | 把 `build/rootfs/` 打包成 Minix v1 镜像 | Linux 0.11 用 Minix 上的 `mkfs` 做根文件系统 |
| `tools/mkbig.py` | 生成测试用的 600 KB 大文件 `/big` | 无 |
| `tools/tour_data.py` | 把最新构建出的地址、i 节点号、块号和文件系统的内容回填进 `docs/tour.html` | 无 |
| `keyboard.c` | 键盘扫描码转字符，支持 Shift 和 Caps Lock，交给终端 | `kernel/chr_drv/keyboard.S` |
| `tty.c` | 终端：一行的编辑、回显、退格、Ctrl+D、Ctrl+C，读一行，写控制台 | `kernel/chr_drv/tty_io.c` |
| `pipe.c` | 管道：一页的环形缓冲区，读写两头 | `fs/pipe.c` |
| `vga.c` | 直接写 VGA 显存、移动硬件光标、整数转字符串 | `kernel/chr_drv/console.c` |
| `string.c` | `memset`、`memcpy`：编译器会把大结构体的赋值和清零编译成对它们的调用 | `include/string.h` |
| `kernel.h`、`io.h` | 各模块共用的声明；端口读写 `inb`、`outb` | `include/asm/io.h` |
| `selftest.c`、`selftest.h` | 自检代码和编号，只在 `make test` 构建的自检内核中生效；用户态的自检写在 `user.c` 中 | 无 |
| `tests/test_kernel.py` | 自动化测试，由 `make test` 调用 | 无 |
| `linker.ld` | 内核链接脚本：链接地址 `0x10000` 和各段顺序 | `Makefile` 中的链接参数 |
| `Makefile` | 汇编、编译、链接、检查内核大小、打包和运行 QEMU | `Makefile`、`tools/build.c` |

生成的文件都在 `build/` 中：写进软盘的 `boot.bin`、`loader.bin`、`kernel.bin`，带符号的 `kernel.elf`，以及软盘镜像 `floppy.img`。自检内核在 `build/selftest/` 下。

参考：[SeaBIOS 读盘实现](https://github.com/coreboot/seabios/blob/master/src/disk.c)、[NASM 引导扇区填充与签名](https://www.nasm.us/doc/nasm14.html)、[QEMU 启动参数](https://www.qemu.org/docs/master/system/qemu-manpage.html)、[OSDev：A20 地址线](https://wiki.osdev.org/A20_Line)、[OSDev：GDT](https://wiki.osdev.org/Global_Descriptor_Table)、[LLD 链接脚本](https://lld.llvm.org/ELF/linker_script.html)、[OSDev：IDT](https://wiki.osdev.org/Interrupt_Descriptor_Table)、[OSDev：8259 PIC](https://wiki.osdev.org/8259_PIC)、[OSDev：PIT](https://wiki.osdev.org/Programmable_Interval_Timer)。
