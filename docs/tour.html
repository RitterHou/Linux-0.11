learning 分支 · 照着 Linux 0.11 从零写的 x86 内核

从上电到用户态

按下电源后，要经过好几段代码接力，一个普通程序才能在受保护的环境里运行，最后从硬盘上装入一个 shell，等你敲命令。屏幕第一行每多出一个字母，就说明又走通了一段。


      
在浏览器里重现的内核屏幕，硬盘上的文件取自真实的镜像。开机完成后点一下屏幕，就能在 shell 里敲命令：ls /bin | grep e、cd /etc、cat issue、echo hi > /tmp/a、df、ps、letter D &、exit。直接运行 cat 或 wc 时，按 Ctrl+D 结束输入。

    01
    
    开机：把程序从软盘搬进内存
    
    
    CPU 只能执行内存里的代码，而程序都躺在软盘上。三段程序像接力一样，每一段把下一段搬进内存，再把执行权交给它。
    
  
    
  
    
    
    
    
    
    
    
    
    展开细节
      
      
    • BIOS 只认“柱面、磁头、扇区”（CHS）地址。loader 先用 int 0x13 AH=08h 问出每道 18 个扇区、2 个磁头，再把 LBA 换算：扇区 = LBA mod 18 + 1，磁头 = (LBA ÷ 18) mod 2，柱面 = LBA ÷ 36。例如 LBA 20 是柱面 0、磁头 1、扇区 3。
      • 
      
    • 每次只读 512 字节，目标地址按 512 对齐，永远不会跨越 64 KB 边界（软驱 DMA 的限制）。读失败先复位磁盘再试，最多 3 次。读完关掉软驱马达。
      • 
      
    • 读多少个扇区由 Makefile 按 kernel.bin 的实际大小算出，在汇编 loader 时传进去。
      • 
      
    • Linux 0.11 的 bootsect.s 做的是同一件事：把 setup 读到 0x90200，把内核读到 0x10000。
      • 
    
    
  
    

    



    
  
    
    02
    
    换挡：从 16 位实模式到 32 位保护模式
    
    
    开机时 CPU 模仿 1978 年的 8086，只能看见 1 MB 内存，也没有任何保护。要用上 4 GB 地址和特权级，得按顺序拨动五个开关，CPU 计算地址的方法也随之完全改变。
    
  
    
  
    
    
    
      
    
        
    实模式 16 位 · 1 MB
    
        
    段 0x1000× 16 +偏移 0x0042=0x10042
    
        
    • 地址直接由段值算出，最大约 1 MB
    • 任何代码都能读写任何地址
    • 可以调用 BIOS 读盘、显示字符
    
      
    
      
      
        
    1. cli先关中断：切换时还没有新的中断表
      2. 
        
    2. 打开 A20第 21 根地址线默认被屏蔽，不开就够不着 1 MB 以上
      3. 
        
    3. lgdt告诉 CPU 段描述符表在哪里
      4. 
        
    4. CR0.PE = 1这一位一置上，就进入保护模式
      5. 
        
    5. jmp 0x08:…远跳转换上新的代码段，开始执行 32 位代码
      6. 
      
    
      
    
        
    保护模式 32 位 · 4 GB
    
        
    选择子 0x08→GDT 第 1 项 基址 0+偏移 0x10042=0x10042
    
        
    • 段寄存器里放的是表的下标，基址和界限查表得到
    • 有特权级：内核 0 级，用户程序 3 级
    • BIOS 不能再用，只能直接写显存
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • loader 里的 GDT 只有 3 项：空描述符、代码段 0x08、数据段 0x10，基址都是 0、界限 4 GB（平坦段），所以偏移就等于物理地址。
      • 
      
    • 进入内核后，gdt_init() 换上内核自己的 10 项 GDT：除了这两段，还有 3 个 TSS 和两个 DPL 3 的用户段（0x33、0x3B）。
      • 
      
    • A20 用端口 0x92 打开；Linux 0.11 的 setup.s 用的是更老的键盘控制器方法。

    03
    
    开张：内核一项项准备好
    
    
    内核拿到 CPU 后，按固定顺序把各个部件准备好。顺序很要紧：比如中断表没装好就开中断，第一次中断就会让 CPU 重启。右边是每一步之后屏幕第一行的样子。
    
  
    
  
    
    
    
    
    
  
    

    



    
  
    
    04
    
    中断：硬件怎样打断 CPU
    
    
    CPU 不会一直盯着键盘。按键时，信号沿着一条固定的路传过来，CPU 放下手里的事，查表找到处理函数，处理完再回到原处。
    
  
    
  
    
    
    
      
    
        
        
      
    
      
    
    
    
    
    
    
  
    

  
    
    
    处理之前，先把现场存到栈上
    
    
    
      
    
        
        
      
    
    
    
    
    
      
    
      
    
        
    
        
    CPU 自动压入入口 isrN 压入isr_common 压入
    
        
    
      
    
    
    
    
    展开细节
      
      
    • 压完以后，从栈顶往上看正好是 C 语言里的 struct interrupt_frame，于是把栈顶地址当参数交给 interrupt_dispatch()，C 代码就能读写被打断时的每个寄存器。系统调用的返回值就是改写其中的 EAX 交回去的。
      • 
      
    • BIOS 把键盘、定时器的中断号放在 0x08～0x0F，正好撞上 CPU 异常 8～15。pic_init() 重新设置 8259，把它们挪到 0x20～0x2F，Linux 0.11 的 setup.s 做的是同一件事。
      • 
      
    • interrupt_dispatch() 先回 8259 一个 EOI（处理完了），它才会送下一个中断。必须先发再处理：定时器处理函数可能切换任务，新任务不会回到这里补发。
      • 
    
    
  
    

    



    
  
    
    05
    
    分页：每个地址都要翻译一次
    
    
    打开分页后，程序用的地址只是一个门牌号。CPU 把它拆成三段，查两张表，才知道真正的内存位置；查不到或没有权限，就触发缺页异常。缺页不一定是错：用户栈所在的 4 MB 开机时一页都没映射，任务 B 用到哪页，内核就在缺页异常里补哪页。挑一个地址试试。
    
  
    
  
    
    
    
    
    
      
    
      
    
    
    
    
    
      
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 页目录和页表各有 1024 项，每项 4 字节，一张表正好一页（4 KB）。一张页表管 4 MB，4 张页表一一对应地映射前 16 MB：虚拟地址等于物理地址，所以打开分页的那一刻代码照常运行。
      • 
      
    • 第 0 页故意不映射，空指针一碰就出错；0xC0000000 也映射到显存，同一块内存有了两个地址，第 0 行的 V 就是从这个地址写进去的。
      • 
      
    • 只有用户程序的代码页和用户空间里分配了的页打开了用户位，其中代码页只读。CPU 要求页目录项和页表项两层都允许才放行。内核在特权级 0 不受只读位限制（CR0.WP 为 0）。
      • 
      
    • 缺页时内核先看两件事：是不是“页不存在”（错误码第 0 位为 0），地址在不在用户空间 0x40000000～0x403FFFFF。都是就从 get_free_page() 拿一页清零的物理页填进页表，返回后 CPU 重新执行那条指令；页表本身也是第一次缺页时才分配的。Linux 0.11 的 do_no_page() 做同样的事。任务 B 结束时，这些页全部还给分配器。
      • 
      
    • 缺页时，CPU 把出错的地址放进 CR2；错误码的三位分别表示：页存在吗、是写吗、来自用户态吗。
      • 
      
    • Linux 0.11 不靠页表的用户位隔离内核：它的页表把内核也标成了用户可访问，靠的是每个进程的段基址和界限。
      • 
    
    
  
    

    



    
  
    
    06
    
    轮流：谁在等，就把 CPU 让出去
    
    
    任务 A、B 写一个字母就调用 sleep(2)。内核把它标成睡眠，马上执行一条 ljmp 切到别的任务：CPU 把当前寄存器存进这个任务的快照（TSS），再装入下一个任务的快照。两个都睡着了，就切回空闲的任务 0，CPU 停在 hlt 上。定时器每 10 毫秒响一次，谁睡到时间就叫醒谁；一直不睡的任务，用完 20 个 tick 的时间片也会被强行切走。
    
  
    
  
    
    
    
      
    
      
    
      
    
    
    
    
      
    
        CPU
        
    
        
    
        
    
        
    
        
    任务 A任务 B空闲
    
      
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • TSS 是 CPU 规定格式的 104 字节。GDT 第 3、4、5 项分别指向任务 0（开机时的 kmain）、A、B 的 TSS，选择子 0x18、0x20、0x28。
      • 
      
    • sleep 先把任务标成睡眠、记下醒来的 tick，再调用 reschedule() 切走，这两步之间关着中断。Linux 0.11 的 sleep_on() 也是先改 current->state，再调用 schedule()。
      • 
      
    • 空闲比例是抽样算出来的：每个 tick 看一眼此刻谁占着 CPU。Linux 0.11 的 do_timer() 用同样的办法给当前进程记 utime、stime。正常运行时接近 100%：两个任务每 2 个 tick 才醒来写一个字母。
      • 
      
    • 被叫醒的任务不会马上抢走别人的 CPU，要等正在运行的任务睡下或用完时间片。Linux 0.11 也是这样：do_timer() 只在当前进程的 counter 减到 0 时才调用 schedule()。
      • 
      
    • CR3 只装入不保存，每个 TSS（包括任务 0 的）都要预先填好页目录地址。审查时发现任务 0 的漏填了：切回任务 0 时，CPU 会把物理地址 0 当成页目录，直接三重错误重启。现在每 2 个 tick 就要切回任务 0 一次，不修这个问题内核根本跑不起来。
      • 
    
    
  
    

    



    
  
    
    07
    
    隔离：用户程序与内核之间有一道墙
    
    
    任务 B 是一个普通程序，运行在特权级 3。它碰不到内核的内存，也不能执行关中断这类指令。想在屏幕上写一个字母，唯一的办法是穿过墙上那扇门：执行 int 0x80 发起系统调用，由内核检查之后替它去写。
    
  
    
  
    
    
    
      
    
        
        
        
      
    
      
    
    
    
    
    
    
    
    
      
    用到栈上还没分配的页不算错：页在用户空间里→ 缺页，内核补上一页，接着运行
    
      
    直接读写内核内存页表里内核的页没有用户位→ #PF，任务被结束
    
      
    改写自己的代码用户代码页是只读的→ #PF，任务被结束
    
      
    执行 cli、hlt、in、out特权指令，EFLAGS 的 IOPL 为 0→ #GP，任务被结束
    
      
    把内核地址交给 write内核先检查指针是否在用户的页里→ 返回 -1
    
    
    
    
    展开细节
      
      
    • 穿过门时 CPU 要换栈：用户栈不可信，CPU 从任务 B 的 TSS 取出 ss0:esp0，换到它的内核栈，再压入用户态的 SS、ESP、EFLAGS、CS、EIP。返回时 iret 看见 CS 的低 2 位是 3，就把这几项弹回去，回到用户态。
      • 
      
    • 调用约定和 Linux 0.11 一样：EAX 是调用号，EBX、ECX、EDX 是参数，返回值放回 EAX。现在有 write、getpid、sleep、exit 四个调用。
      • 
      
    • 用户程序出错只结束它自己：内核在第 7 行写一行黄字，把任务标记为已结束，切到下一个任务。NMI、双重错误、机器检查来自硬件，不算用户程序的错，照样显示红色异常面板。
      • 
      
    • Linux 0.11 不逐个检查用户指针：内核通过用户数据段（FS）读用户内存，越界由段界限挡住。这里所有段都是平坦的，只能显式检查。
      • 
    
    
  
    

    



    
  
    
    08
    
    进程：fork、写时复制、exit 与 waitpid
    
    
    init 调用 fork，复制出一个子进程。内核并不复制内存，只复制页表：父子的页表项指向同一批物理页，两边都改成只读，打上写时复制的记号。谁先写，谁就在缺页异常里得到自己的一份。子进程结束后先变成僵尸，等父进程用 waitpid 取走退出码，才彻底收走。
    
  
    
  
    
    
    
      
    
      
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 子进程的 TSS 直接用父进程进入系统调用时栈上保存的寄存器：EIP 是 int 0x80 的下一条指令，只把 EAX 改成 0。子进程第一次被调度时，硬件任务切换直接把它放回用户态，好像 fork 刚返回 0。Linux 0.11 的 copy_process() 也是这样。
      • 
      
    • 写时复制的记号是页表项的第 9 位：CPU 不用这一位，留给操作系统。本来就只读的页（程序的代码）不打记号，写它仍是错误，程序会被结束。
      • 
      
    • 内核替用户写内存时（例如 waitpid 把退出码写回父进程的变量）也可能碰上共享的只读页。内核打开了 CR0 的 WP 位，特权级 0 写只读页同样会缺页，走同一条复制的路。386 没有这一位，所以 Linux 0.11 要先调用 verify_area()。
      • 
      
    • 任务表有 16 个槽。去掉任务 0、A 和 init，测试里正好能 fork 13 次，第 14 次返回 -1。
      • 
    
    
  
    

    



    
  
    
    09
    
    硬盘与文件系统：按路径找到一个文件
    
    
    硬盘上是 Linux 0.11 用的 Minix 文件系统：每块 1 KB，开头是超级块和两张位图，接着是 i 节点表，后面是数据块。目录也是文件，内容是一条条“名字 → i 节点号”。打开 /etc/issue，就是从根目录起一段段查下去。读过的块留在缓冲区缓存里，再用到就不碰硬盘。
    
  
    
  
    
    
    
    
    
      
    
      
    缓冲区缓存
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 每次未命中都要读两个扇区：hd_read() 写好 LBA，发 READ SECTORS 命令，然后睡在等待队列上；硬盘准备好数据后拉 IRQ14，中断处理函数用 rep insw 读走 256 个字，再叫醒它。CPU 正闲着的话马上切回去，不必等下一个定时器中断。
      • 
      
    • i 节点里有 9 个块号：前 7 个直接指向数据块；第 8 个指向一个间接块，里面是 512 个块号；第 9 个指向二级间接块。600 KB 的测试文件 /big 要用到二级间接块。
      • 
      
    • 缓冲区缓存只有 16 个缓冲区。没有的块，就挑一个没人在用、最久没用过的缓冲区换掉。别的任务正在读同一块，就睡下等它读完。
      • 
      
    • 打开的文件在文件表里占一项，记下 i 节点和读写位置，文件描述符指向它。fork 之后父子共用这一项，读写位置也共用。
      • 
    
    
  
    

    



    
  
    
    10
    
    exec 与 shell：敲下 ls /bin 之后
    
    
    shell 是硬盘上的一个普通程序。它读一行命令，fork 出子进程，子进程用 exec 把自己换成硬盘上的 /bin/ls：内核建一份新的地址空间，把程序装进去，在栈顶摆好参数，系统调用一返回，CPU 就从新程序的第一条指令开始执行。
    
  
    
  
    
    
    
      
    
      
    
        
    
        
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 终端按“规范模式”工作：敲的字符先放进当前这一行，内核回显；退格只删自己敲的；回车后这一行才交给 read(0)。shell 在等待队列上睡着等，ps 里它的状态是 B。
      • 
      
    • 程序找到终端靠设备文件：/dev/tty0 是控制台，/dev/tty1 是第 6 行。i 节点的类型是字符设备，第一个块号存着设备号 4,0 或 4,1，与 Linux 0.11 相同。init 把 /dev/tty0 打开三次，得到 0、1、2 号描述符，再 exec shell。
      • 
      
    • 用户程序是 ELF 文件，链接在用户空间的底部 0x40000000：代码页只读，数据页可写，.bss 是 exec 分出来的清零的页。中途任何一步失败，exec 就收回新的页目录、返回 -1，原来的程序不受影响。
      • 
      
    • Linux 0.11 读的是 a.out 格式，程序的页在缺页时才从文件里读，同一个程序的进程可以共用代码页。
      • 
    
    
  
    

    



    
  
    
    11
    
    管道：ls /bin | wc 是怎么接起来的
    
    
    管道是内核里一页大小的缓冲区，有读、写两头，各占一个文件描述符。shell 先建管道再 fork，子进程照抄描述符表，再用 close 加 dup 把管道的一头挪到 0 号或 1 号上。ls 照常写 1 号，wc 照常读 0 号，两个程序都不知道中间是一个管道。
    
  
    
  
    
    
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 缓冲区是 4096 字节的环形缓冲区：写满了，写的一方睡下等；读空了，读的一方睡下等。cat /big | wc 让 600 KB 经过这一页，一个字节也不丢，测试逐个核对 wc 数出的 2400 行、7201 个词、614400 个字节。
      • 
      
    • 读的一方怎么知道结束了？写的一头的描述符全都关掉之后，read 读完剩下的就返回 0。所以每个进程都要把用不着的那一头关掉：只要还有人拿着写的一头，wc 就会一直等下去。
      • 
      
    • 读的一头全关了还往里写，write 返回 -1。Linux 0.11 的 write_pipe() 这时还给写的进程发 SIGPIPE 信号，这里还没有信号。
      • 
      
    • > 文件、>> 文件、< 文件 用的是同一个办法：子进程在 exec 之前打开文件，close(1) 或 close(0) 再 dup，文件就接到了 1 号或 0 号描述符上。
      • 
      
    • dup 返回最小的空闲描述符，所以要先 close 再 dup。Linux 0.11 还有 dup2(old, new)，一步就能指定接到哪个描述符上，这里没有实现。
      • 
    
    
  
    

    



    
  
    
    12
    
    写文件：echo hi > /tmp/a 改了硬盘上的哪几块
    
    
    读文件只是查表，写文件要改表。新建一个文件，要在 i 节点位图里找一个空位，再在目录里加一项；写进内容，要在区块位图里再找一个空位。每改一块，马上写回硬盘。下面的块号和 i 节点号都是真机上的。
    
  
    
  
    
    
    
    
    
    
    
    
    
    
    展开细节：当前目录、文件系统锁、删掉开着的文件
      
      
    • 当前目录：每个任务记着当前目录的路径，fork 时照抄。路径不是 / 开头的，系统调用先把它接在当前目录后面，再交给 namei()。. 和 .. 不用特别处理：它们本来就是每个目录里的头两项，/etc/.. 查到的就是根目录，根目录的 .. 指向它自己。
      • 
      
    • cd 先确认目标是一个目录，再按字面去掉多余的 /、. 和 .. 存起来，所以 cd /bin/../etc/./ 之后 pwd 打印 /etc。cd 必须是 shell 的内建命令：fork 出子进程去换目录，换的只是子进程自己的，子进程一结束就没了。
      • 
      
    • Linux 0.11 的 current->pwd 记的是当前目录的 i 节点，没有 getcwd 系统调用，pwd 要沿着 .. 一级级往上，在上一级目录里找自己的名字。这里记的是路径，getcwd 直接复制出来就行。
      • 
      
    • 文件系统锁：读写硬盘会睡，两个任务同时改文件系统，可能分到同一块。所以改文件系统的操作、读文件、查路径、exec 装入程序，都要先拿到一把锁。Linux 0.11 给每个 i 节点、每个缓冲区各加一把锁，并发更好，道理相同。
      • 
      
    • 删掉开着的文件：目录里那一项清掉了，打开它的程序还能接着读写；最后一个描述符关掉时，链接数是 0，才真正放掉它的块和 i 节点。
