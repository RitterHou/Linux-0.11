从上电到用户态

一个从零写出来的 32 位 x86 小内核。它从一张 1.44 MB 软盘启动，经过两段引导程序进入保护模式，再一步步加上中断、分页、任务切换、系统调用和用户态。每一步都对照 Linux 0.11 的同名机制，并由自动化测试在 QEMU 中验证。

    全貌
    
三层：硬件、内核、用户程序

    软盘与读盘
    
    LBA 换算成柱面、磁头、扇区
    
    
    软盘没有文件系统，三段程序按扇区紧挨着放。BIOS 只认 CHS 地址，loader 先用 int 0x13 AH=08h 问出每道扇区数和磁头数，再把连续编号的 LBA 逐个换算。点下面任意一个扇区，看它在哪个柱面、哪个磁头。
    
  
    
  
    
    
    
      LBA 0：boot.bin
      LBA 1：loader.bin
      LBA 2 起：kernel.bin（32 个扇区）
    
    
    
    
    
    
      
    LBA20
    
      
    柱面 = LBA ÷ 18 ÷ 20
    
      
    磁头 = (LBA ÷ 18) mod 21
    
      
    扇区 = LBA mod 18 + 13
    
      
    读到的内存地址0x12400
    
    
    
    
    每次只读一个 512 字节的扇区，目标地址按 512 对齐，所以永远不会跨过 64 KB 边界（软驱 DMA 的限制）。Linux 0.11 的 bootsect.s 一次读一整条磁道以加快速度，原理相同。
    
  
    

    



    
  
    
    中断与栈
    
    一次中断，栈上被压了什么
    
    
    无论是定时器、键盘、CPU 异常还是系统调用，都走同一条路：CPU 压一部分，入口代码补齐，isr_common 再保存其余寄存器，栈上就成了 C 语言里的 struct interrupt_frame。从用户态进入时，CPU 还要先换栈。
    
  
    
  
    
    
    
      
      
    
    
    
    
      
      
      
      
    
    
    
    
      
    
      
    
    
    
    
    
      CPU 自动压入
      入口 isrN 压入
      isr_common 压入
    
    
  
    
  
    
    
    8259 与 EOI
    
    
      
      
    • BIOS 把主片的 IRQ0～7 放在中断号 0x08～0x0F，正好与 CPU 异常 8～15 重叠，不改的话定时器中断会被当成双重错误。pic_init() 重新初始化两片 8259，把 IRQ 挪到 0x20～0x2F，和 Linux 0.11 的 setup.s 一样。
      • 
      
    • 8259 送出一个中断后，要等 CPU 回 EOI 才送下一个。这里先发 EOI 再调用处理函数：定时器处理函数可能切换任务，新任务第一次运行时从入口开始，不会回到原来的处理函数，EOI 留到最后就永远发不出去了。
      • 
      
    • 第 0x80 项是 DPL 3 的陷阱门，其余是 DPL 0 的中断门。陷阱门进入时不关中断，系统调用执行期间定时器照常工作，sleep 才等得到 tick。
      • 
    
    
  
    

    



    
  
    
    分页
    
    一个虚拟地址的两级查表
    
    
    打开分页后，CPU 发出的每个地址都要查表：高 10 位选页目录项，中间 10 位选页表项，低 12 位是页内偏移。页表项上的“存在”和“用户”两个位，决定了这次访问是成功、还是触发 14 号缺页异常。选一个地址试试。
    
  
    
  
    
    
    
      
      
      
        
        
      
      
        
        
      
    
    
    
    
    
    
    
    
    
    
  
    

    



    
  
    
    任务切换
    
    一条 ljmp，CPU 换了一整套寄存器
    
    
    每个任务有一个 104 字节的 TSS，存着它的全部寄存器。定时器每 20 个 tick 让 schedule() 远跳转到下一个任务的 TSS 选择子：CPU 把当前寄存器存进当前任务的 TSS，再从目标 TSS 装入，目标任务就从上次停下的地方接着跑。Linux 0.11 的 switch_to 也是这一条指令。
    
  
    
  
    
    
    
      
      
      
      
      
    
    
    
    
    
    
    
    
    
    
    
    CR3 只装入、不保存：CPU 从目标 TSS 装入 CR3，却不会把当前 CR3 存回旧 TSS，所以每个 TSS（包括任务 0 的）都要预先填好页目录地址。注意保存下来的值：切换总是发生在定时器中断处理函数里，所以无论任务 A 还是任务 B，被切走时 CS 都是内核的 0x08，EIP 在 switch_to() 里。任务 B 在用户态的 CS、EIP、ESP 不在 TSS 里，而在它内核栈顶 CPU 压入的那几项中，中断返回时才恢复。
    
  
    

    



    
  
    
    系统调用与用户态
    
    用户程序怎样请内核帮忙，又被挡在哪里
    
    
    任务 B 运行在特权级 3：它能执行的代码和能访问的内存，只有链接脚本放进 .user 段的那两页。想输出一个字母，只能把参数放进寄存器、执行 int 0x80，由内核检查之后替它去写。

    机制这里的做法Linux 0.11 的做法
    
      
        
    用户段GDT 第 6、7 项：DPL 3 的代码段 0x33、数据段 0x3B每个进程 LDT 中的 0x0f、0x17
    
        
    进入用户态任务 B 的 TSS 中段选择子都是用户段，硬件任务切换装入时直接进入特权级 3move_to_user_mode() 构造返回现场后执行 iret
    
        
    内核栈TSS 的 ss0:esp0 指向任务 B 的 4 KB 内核栈copy_process() 把 esp0 设为进程内核栈顶
    
        
    内存保护只有 .user 的页打开页表项的用户位，其中代码页只读不靠页表：head.s 把前 16 MB（内核在内）都映射成 7（存在、可写、用户）；用户程序的段基址为 进程号 × 64 MB、界限有限，形成的地址落不到内核那里
    
        
    检查用户指针user_range_ok() 显式检查经 FS（用户数据段）用 get_fs_byte() 读写，越界由段界限挡住；verify_area() 是写用户内存前处理写时复制
    
        
    用户程序出错只结束该任务，第 7 行写黄色消息；NMI、双重错误、机器检查例外，照样显示异常面板die() 调用 do_exit(11)
    
        
    内核态抢占会：任务 A 和系统调用都可能在内核里被切走，共享数据要关中断保护不会：do_timer() 中 if (!cpl) return;

    一次独立代码审查
    
    
    功能做完后，另请一个代理只读地通读全部代码。它找到的问题都先复现、再修复，并补上能抓住它的测试：
    
    
      
      
    • 所有任务结束时会三重错误。任务切换时 CPU 从新 TSS 装入 CR3，但不会把当前 CR3 存回旧 TSS；任务 0 的 TSS 里 CR3 一直是 0，切回去时页目录就成了物理地址 0。补上 tss[0].cr3，新测试让任务 A、B 都 exit。
      • 
      
    • 开中断前的按键会让键盘永久失灵。没人读的字节让 IRQ1 一直是高电平，8259 是边沿触发，再也等不到上升沿。keyboard_init() 先读光缓冲区。
      • 
      
    • NMI 被算成用户程序的错。任务 B 在用户态时来了 NMI，会被“结束”；现在硬件类异常一律显示面板。测试先用监视器 stop 暂停、确认在用户态，再注入 NMI。
      • 
      
    • 引导读盘不重试、软驱马达不关、几何参数可能除以零；按住 Caps Lock 的自动重复会来回切换；换行后的退格对不上；测试脚本超时后会读错位。
      • 
      
    • README 里几处与 Linux 0.11 的对照写错了：Linux 0.11 靠段而不是页表隔离内核，verify_area() 是写时复制而不是范围检查，do_timer() 不抢占内核态。
      • 
    
    
  
    
  
    
    
    每个测试都先证明自己能失败
    
    
    新加一项测试时，都在临时副本里故意把代码改坏，确认这项测试真的会报错，再提交。这个习惯抓到过好几处“测试永远通过”的问题：
    
    
      
      
    • QEMU 的 TCG 模拟不检查通过空选择子访问内存，用空选择子测“中断入口换段”永远通过；改用基址为 1 MB 的段后才测得出来。
      • 
      
    • clang 会把 1 / zero 优化成不含除法的比较，除零自检根本不触发异常；改用内联汇编。
      • 
      
    • SeaBIOS 开机时会把常规内存清零，所以在 QEMU 里看不出 .bss 没清零的后果。
      • 
      
    • 远跳转到自己的 TSS 会因为它处于“忙”状态触发 #GP：去掉 schedule() 里的判断后，只剩一个任务时立刻出现错误码 0x20 的异常面板。
