learning 分支 · 照着 Linux 0.11 从零写的 x86 内核

从上电到用户态

按下电源后，要经过好几段代码接力，一个普通程序才能在受保护的环境里运行，最后从硬盘上装入一个 shell，等你敲命令。屏幕第一行每多出一个字母，就说明又走通了一段。


      
在浏览器里重现的内核屏幕，硬盘上的文件取自真实的镜像，shell 照着 user/sh.c 写。开机完成后点一下屏幕就能敲命令：ls -l /bin | grep s、for i in 1 2 3; do echo $i; done、sleep 100 再按 Ctrl+Z 然后 jobs、bg、fg，su user 以后 cat /etc/shadow，mount /dev/hdb /mnt。方向键改这一行、翻历史；Ctrl+C 结束前台程序；直接运行 cat 时按 Ctrl+D 结束输入。

    01
    
    开机：把程序从软盘搬进内存
    
    
    CPU 只能执行内存里的代码，而程序都躺在软盘上。三段程序像接力一样，每一段把下一段搬进内存，再把执行权交给它。
    
  
    
  
    
    
    
    
    
    
    
    
    展开细节
      
      
    • BIOS 只认“柱面、磁头、扇区”（CHS）地址。loader 先用 int 0x13 AH=08h 问出每道 18 个扇区、2 个磁头，再把 LBA 换算：扇区 = LBA mod 18 + 1，磁头 = (LBA ÷ 18) mod 2，柱面 = LBA ÷ 36。例如 LBA 20 是柱面 0、磁头 1、扇区 3。
      • 
      
    • 每次只读 512 字节，目标地址按 512 对齐，永远不会跨越 64 KB 边界（软驱 DMA 的限制）。读失败先复位磁盘再试，最多 3 次。读完关掉软驱马达。
      • 
      
    • 读多少个扇区由 Makefile 按 kernel.bin 的实际大小算出，在汇编 loader 时传进去。
      • 
      
    • Linux 0.11 的 bootsect.s 做的是同一件事：把 setup 读到 0x90200，把内核读到 0x10000。
      • 
    
    
  
    

    



    
  
    
    02
    
    换挡：从 16 位实模式到 32 位保护模式
    
    
    开机时 CPU 模仿 1978 年的 8086，只能看见 1 MB 内存，也没有任何保护。要用上 4 GB 地址和特权级，得按顺序拨动五个开关，CPU 计算地址的方法也随之完全改变。
    
  
    
  
    
    
    
      
    
        
    实模式 16 位 · 1 MB
    
        
    段 0x1000× 16 +偏移 0x0042=0x10042
    
        
    • 地址直接由段值算出，最大约 1 MB
    • 任何代码都能读写任何地址
    • 可以调用 BIOS 读盘、显示字符
    
      
    
      
      
        
    1. cli先关中断：切换时还没有新的中断表
      2. 
        
    2. 打开 A20第 21 根地址线默认被屏蔽，不开就够不着 1 MB 以上
      3. 
        
    3. lgdt告诉 CPU 段描述符表在哪里
      4. 
        
    4. CR0.PE = 1这一位一置上，就进入保护模式
      5. 
        
    5. jmp 0x08:…远跳转换上新的代码段，开始执行 32 位代码
      6. 
      
    
      
    
        
    保护模式 32 位 · 4 GB
    
        
    选择子 0x08→GDT 第 1 项 基址 0+偏移 0x10042=0x10042
    
        
    • 段寄存器里放的是表的下标，基址和界限查表得到
    • 有特权级：内核 0 级，用户程序 3 级
    • BIOS 不能再用，只能直接写显存
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • loader 里的 GDT 只有 3 项：空描述符、代码段 0x08、数据段 0x10，基址都是 0、界限 4 GB（平坦段），所以偏移就等于物理地址。
      • 
      
    • 进入内核后，gdt_init() 换上内核自己的 10 项 GDT：除了这两段，还有 3 个 TSS 和两个 DPL 3 的用户段（0x33、0x3B）。
      • 
      
    • A20 用端口 0x92 打开；Linux 0.11 的 setup.s 用的是更老的键盘控制器方法。

    03
    
    开张：内核一项项准备好
    
    
    内核拿到 CPU 后，按固定顺序把各个部件准备好。顺序很要紧：比如中断表没装好就开中断，第一次中断就会让 CPU 重启。右边是每一步之后屏幕第一行的样子。
    
  
    
  
    
    
    
    
    
  
    

    



    
  
    
    04
    
    中断：硬件怎样打断 CPU
    
    
    CPU 不会一直盯着键盘。按键时，信号沿着一条固定的路传过来，CPU 放下手里的事，查表找到处理函数，处理完再回到原处。
    
  
    
  
    
    
    
      
    
        
        
      
    
      
    
    
    
    
    
    
  
    

  
    
    
    处理之前，先把现场存到栈上
    
    
    
      
    
        
        
      
    
    
    
    
    
      
    
      
    
        
    
        
    CPU 自动压入入口 isrN 压入isr_common 压入
    
        
    
      
    
    
    
    
    展开细节
      
      
    • 压完以后，从栈顶往上看正好是 C 语言里的 struct interrupt_frame，于是把栈顶地址当参数交给 interrupt_dispatch()，C 代码就能读写被打断时的每个寄存器。系统调用的返回值就是改写其中的 EAX 交回去的。
      • 
      
    • BIOS 把键盘、定时器的中断号放在 0x08～0x0F，正好撞上 CPU 异常 8～15。pic_init() 重新设置 8259，把它们挪到 0x20～0x2F，Linux 0.11 的 setup.s 做的是同一件事。
      • 
      
    • interrupt_dispatch() 先回 8259 一个 EOI（处理完了），它才会送下一个中断。必须先发再处理：定时器处理函数可能切换任务，新任务不会回到这里补发。
      • 
    
    
  
    

    



    
  
    
    05
    
    分页：每个地址都要翻译一次
    
    
    打开分页后，程序用的地址只是一个门牌号。CPU 把它拆成三段，查两张表，才知道真正的内存位置；查不到或没有权限，就触发缺页异常。缺页不一定是错：用户栈所在的 4 MB 开机时一页都没映射，任务 B 用到哪页，内核就在缺页异常里补哪页。挑一个地址试试。
    
  
    
  
    
    
    
    
    
      
    
      
    
    
    
    
    
      
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 页目录和页表各有 1024 项，每项 4 字节，一张表正好一页（4 KB）。一张页表管 4 MB，4 张页表一一对应地映射前 16 MB：虚拟地址等于物理地址，所以打开分页的那一刻代码照常运行。
      • 
      
    • 第 0 页故意不映射，空指针一碰就出错；0xC0000000 也映射到显存，同一块内存有了两个地址，第 0 行的 V 就是从这个地址写进去的。
      • 
      
    • 只有用户程序的代码页和用户空间里分配了的页打开了用户位，其中代码页只读。CPU 要求页目录项和页表项两层都允许才放行。内核在特权级 0 不受只读位限制（CR0.WP 为 0）。
      • 
      
    • 缺页时内核先看两件事：是不是“页不存在”（错误码第 0 位为 0），地址在不在用户空间 0x40000000～0x403FFFFF。都是就从 get_free_page() 拿一页清零的物理页填进页表，返回后 CPU 重新执行那条指令；页表本身也是第一次缺页时才分配的。Linux 0.11 的 do_no_page() 做同样的事。任务 B 结束时，这些页全部还给分配器。
      • 
      
    • 缺页时，CPU 把出错的地址放进 CR2；错误码的三位分别表示：页存在吗、是写吗、来自用户态吗。
      • 
      
    • Linux 0.11 不靠页表的用户位隔离内核：它的页表把内核也标成了用户可访问，靠的是每个进程的段基址和界限。
      • 
    
    
  
    

    



    
  
    
    06
    
    轮流：谁在等，就把 CPU 让出去
    
    
    任务 A、B 写一个字母就调用 sleep(2)。内核把它标成睡眠，马上执行一条 ljmp 切到别的任务：CPU 把当前寄存器存进这个任务的快照（TSS），再装入下一个任务的快照。两个都睡着了，就切回空闲的任务 0，CPU 停在 hlt 上。定时器每 10 毫秒响一次，谁睡到时间就叫醒谁；一直不睡的任务，用完 20 个 tick 的时间片也会被强行切走。
    
  
    
  
    
    
    
      
    
      
    
      
    
    
    
    
      
    
        CPU
        
    
        
    
        
    
        
    
        
    任务 A任务 B空闲
    
      
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • TSS 是 CPU 规定格式的 104 字节。GDT 第 3、4、5 项分别指向任务 0（开机时的 kmain）、A、B 的 TSS，选择子 0x18、0x20、0x28。
      • 
      
    • sleep 先把任务标成睡眠、记下醒来的 tick，再调用 reschedule() 切走，这两步之间关着中断。Linux 0.11 的 sleep_on() 也是先改 current->state，再调用 schedule()。
      • 
      
    • 空闲比例是抽样算出来的：每个 tick 看一眼此刻谁占着 CPU。Linux 0.11 的 do_timer() 用同样的办法给当前进程记 utime、stime。正常运行时接近 100%：两个任务每 2 个 tick 才醒来写一个字母。
      • 
      
    • 被叫醒的任务不会马上抢走别人的 CPU，要等正在运行的任务睡下或用完时间片。Linux 0.11 也是这样：do_timer() 只在当前进程的 counter 减到 0 时才调用 schedule()。
      • 
      
    • 挑谁照 Linux 0.11 的 schedule()：每个任务有 counter（这一轮还能运行几个 tick）和 priority（每轮补多少，默认 20）。能运行的任务里挑 counter 最多的；都用完了，每个任务（睡着的也算）的 counter 变成 counter / 2 + priority。常睡的任务攒着一半没用完的，醒来排在前面，等键盘的 shell 反应就快。
      • 
      
    • nice 改的就是 priority = 20 − nice：nice 0 和 nice 19 的两个一直空转的程序，CPU 按 20:1 分；只有 root 能把 nice 调低。ps -l 显示 PRI、NI 和用了多少 CPU 时间，time 命令 报告过了多久、用户态和内核态各用了多少。
      • 
      
    • CR3 只装入不保存，每个 TSS（包括任务 0 的）都要预先填好页目录地址。审查时发现任务 0 的漏填了：切回任务 0 时，CPU 会把物理地址 0 当成页目录，直接三重错误重启。现在每 2 个 tick 就要切回任务 0 一次，不修这个问题内核根本跑不起来。
      • 
    
    
  
    

    



    
  
    
    07
    
    隔离：用户程序与内核之间有一道墙
    
    
    任务 B 是一个普通程序，运行在特权级 3。它碰不到内核的内存，也不能执行关中断这类指令。想在屏幕上写一个字母，唯一的办法是穿过墙上那扇门：执行 int 0x80 发起系统调用，由内核检查之后替它去写。
    
  
    
  
    
    
    
      
    
        
        
        
      
    
      
    
    
    
    
    
    
    
    
      
    用到栈上还没分配的页不算错：页在用户空间里→ 缺页，内核补上一页，接着运行
    
      
    直接读写内核内存页表里内核的页没有用户位→ #PF，任务被结束
    
      
    改写自己的代码用户代码页是只读的→ #PF，任务被结束
    
      
    执行 cli、hlt、in、out特权指令，EFLAGS 的 IOPL 为 0→ #GP，任务被结束
    
      
    把内核地址交给 write内核先检查指针是否在用户的页里→ 返回 -1
    
    
    
    
    展开细节
      
      
    • 穿过门时 CPU 要换栈：用户栈不可信，CPU 从任务 B 的 TSS 取出 ss0:esp0，换到它的内核栈，再压入用户态的 SS、ESP、EFLAGS、CS、EIP。返回时 iret 看见 CS 的低 2 位是 3，就把这几项弹回去，回到用户态。
      • 
      
    • 调用约定和 Linux 0.11 一样：EAX 是调用号，EBX、ECX、EDX 是参数，返回值放回 EAX。现在有 write、getpid、sleep、exit 四个调用。
      • 
      
    • 用户程序出错只结束它自己：内核在第 7 行写一行黄字，把任务标记为已结束，切到下一个任务。NMI、双重错误、机器检查来自硬件，不算用户程序的错，照样显示红色异常面板。
      • 
      
    • Linux 0.11 不逐个检查用户指针：内核通过用户数据段（FS）读用户内存，越界由段界限挡住。这里所有段都是平坦的，只能显式检查。
      • 
    
    
  
    

    



    
  
    
    08
    
    进程：fork、写时复制、exit 与 waitpid
    
    
    init 调用 fork，复制出一个子进程。内核并不复制内存，只复制页表：父子的页表项指向同一批物理页，两边都改成只读，打上写时复制的记号。谁先写，谁就在缺页异常里得到自己的一份。子进程结束后先变成僵尸，等父进程用 waitpid 取走退出码，才彻底收走。
    
  
    
  
    
    
    
      
    
      
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 子进程的 TSS 直接用父进程进入系统调用时栈上保存的寄存器：EIP 是 int 0x80 的下一条指令，只把 EAX 改成 0。子进程第一次被调度时，硬件任务切换直接把它放回用户态，好像 fork 刚返回 0。Linux 0.11 的 copy_process() 也是这样。
      • 
      
    • 写时复制的记号是页表项的第 9 位：CPU 不用这一位，留给操作系统。本来就只读的页（程序的代码）不打记号，写它仍是错误，程序会被结束。
      • 
      
    • 内核替用户写内存时（例如 waitpid 把退出码写回父进程的变量）也可能碰上共享的只读页。内核打开了 CR0 的 WP 位，特权级 0 写只读页同样会缺页，走同一条复制的路。386 没有这一位，所以 Linux 0.11 要先调用 verify_area()。
      • 
      
    • 任务表有 16 个槽。去掉任务 0、A 和 init，测试里正好能 fork 13 次，第 14 次返回 -1。
      • 
    
    
  
    

    



    
  
    
    09
    
    硬盘与文件系统：按路径找到一个文件
    
    
    硬盘上是 Linux 0.11 用的 Minix 文件系统：每块 1 KB，开头是超级块和两张位图，接着是 i 节点表，后面是数据块。目录也是文件，内容是一条条“名字 → i 节点号”。打开 /etc/issue，就是从根目录起一段段查下去。读过的块留在缓冲区缓存里，再用到就不碰硬盘。
    
  
    
  
    
    
    
    
    
      
    
      
    缓冲区缓存
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 每次未命中都要读两个扇区：hd_read() 写好 LBA，发 READ SECTORS 命令，然后睡在等待队列上；硬盘准备好数据后拉 IRQ14，中断处理函数用 rep insw 读走 256 个字，再叫醒它。CPU 正闲着的话马上切回去，不必等下一个定时器中断。
      • 
      
    • i 节点里有 9 个块号：前 7 个直接指向数据块；第 8 个指向一个间接块，里面是 512 个块号；第 9 个指向二级间接块。600 KB 的测试文件 /big 要用到二级间接块。
      • 
      
    • 缓冲区缓存只有 16 个缓冲区。没有的块，就挑一个没人在用、最久没用过的缓冲区换掉。别的任务正在读同一块，就睡下等它读完。
      • 
      
    • 打开的文件在文件表里占一项，记下 i 节点和读写位置，文件描述符指向它。fork 之后父子共用这一项，读写位置也共用。
      • 
      
    • 挂载：第二块盘 hdb 上是另一个 Minix 文件系统。mount /dev/hdb /mnt 读进它的超级块，记下“挂在 /mnt 上”。查路径走到 /mnt 时换到 hdb 的根目录，在那里查 .. 又回到 /。每个 i 节点、每个缓冲区都多记一个设备号，同一个 i 节点号在两块盘上是两个文件，所以不能跨盘 ln。开着文件、有人的当前目录在里面，就卸不了。Linux 0.11 的 sys_mount() 也是这样，靠 i 节点上的 i_mount 记号在 namei 里换盘。
      • 
      
    • 目录项只是“名字 → i 节点号”，所以一个文件可以有好几个名字：ln a b 在目录里再加一项，指向同一个 i 节点，链接数加一。删掉一个名字（unlink 就是“去掉一个链接”）只是链接数减一，减到 0 才真正收回。mv 就是先 link 新名字、再 unlink 旧名字，内容一个字节也不用搬。
      • 
    
    
  
    

    



    
  
    
    10
    
    exec 与 shell：敲下 ls /bin 之后
    
    
    shell 是硬盘上的一个普通程序。它读一行命令，fork 出子进程，子进程用 exec 把自己换成硬盘上的 /bin/ls：内核建一份新的地址空间，记下程序文件和它的几个段，在栈顶摆好参数，系统调用一返回，CPU 就从新程序的第一条指令开始执行，用到哪一页才从文件里读哪一页。
    
  
    
  
    
    
    
      
    
      
    
        
    
        
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 终端平时按“规范模式”工作：敲的字符先放进当前这一行，内核回显；退格只删自己敲的；回车后这一行才交给 read(0)。cat、login 这些程序读终端时就是这样。shell 读命令时换成原始模式（ioctl 的 TCSETS 关掉 ICANON 和 ECHO），每个键马上交来，自己回显、自己处理方向键，读完再换回去。读的时候它睡在等待队列上，ps 里它的状态是 B。
      • 
      
    • shell 的语法照着 POSIX 的 sh：引号、$变量、$?、$((算式))，; && ||，if、while、for。一条命令先分词，再解析成语法树，执行时才展开变量，所以循环每转一圈都重新换一遍。没写完的（引号没配对、if 没有 fi、末尾是 |）打出 > 接着读。
      • 
      
    • 程序找到终端靠设备文件：/dev/tty0 是控制台，/dev/tty1 是第 6 行，/dev/ttyS0 是串口（COM1，IRQ4），init 在串口上运行 login，make run 的那个终端窗口就接在它上面。i 节点的类型是字符设备，第一个块号存着设备号 4,0 或 4,1，与 Linux 0.11 相同。init 把 /dev/tty0 打开三次，得到 0、1、2 号描述符，再 exec shell。
      • 
      
    • 用户程序是 ELF 文件，链接在用户空间的底部 0x40000000：代码页只读，数据页可写，.bss 在文件里不占地方，用到时补 0。中途任何一步失败，exec 就收回新的页目录、返回 -1，原来的程序不受影响。
      • 
      
    • Linux 0.11 读的是 a.out 格式，也是在缺页时才从文件里读程序的页，同一个程序的进程共用代码页，见第 17 章。
      • 
      
    • 文件开头是 #!/bin/sh 的是脚本：exec 改去装入第一行写着的解释器，参数排成“解释器、脚本的路径、原来的参数”，于是运行脚本就是 sh 脚本，sh 从文件里一行行读命令。新建的文件没有执行权限，要先 chmod 755。Linux 0.11 的 do_execve() 也这样处理 #!。
      • 
    
    
  
    

    



    
  
    
    11
    
    管道：ls /bin | wc 是怎么接起来的
    
    
    管道是内核里一页大小的缓冲区，有读、写两头，各占一个文件描述符。shell 先建管道再 fork，子进程照抄描述符表，再用 close 加 dup 把管道的一头挪到 0 号或 1 号上。ls 照常写 1 号，wc 照常读 0 号，两个程序都不知道中间是一个管道。
    
  
    
  
    
    
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 缓冲区是 4096 字节的环形缓冲区：写满了，写的一方睡下等；读空了，读的一方睡下等。cat /big | wc 让 600 KB 经过这一页，一个字节也不丢，测试逐个核对 wc 数出的 2400 行、7201 个词、614400 个字节。
      • 
      
    • 读的一方怎么知道结束了？写的一头的描述符全都关掉之后，read 读完剩下的就返回 0。所以每个进程都要把用不着的那一头关掉：只要还有人拿着写的一头，wc 就会一直等下去。
      • 
      
    • 读的一头全关了还往里写，写的进程收到 SIGPIPE，默认就被结束；忽略了 SIGPIPE 的，write 返回 -1。Linux 0.11 的 write_pipe() 也是这样。
      • 
      
    • > 文件、>> 文件、< 文件、2> 文件 用的是同一个办法：子进程在 exec 之前打开文件，用 dup2 接到 1、0 或 2 号上；2>&1 就是 dup2(1, 2)。出错的消息都写 2 号，所以管道里只有数据。
      • 
      
    • 只有 dup 的时候，要先 close 再 dup，借它“返回最小的空闲描述符”接到想要的号上。dup2(old, new) 一步到位，Linux 0.11 也有它。fcntl(fd, F_SETFD, FD_CLOEXEC) 让描述符在 exec 时自动关掉：sh 读脚本用的那个描述符，就不会留给它运行的命令。
      • 
      
    • 命名管道：mkfifo /tmp/ff 在目录里建一个类型是 p 的 i 节点，谁都能建。不相干的两个进程各自 open 它：读的一头要等有人打开写的一头，写的一头也要等读的；两头都开了，用的就是同一个管道。先 cat /tmp/ff &，再 echo hi > /tmp/ff，后台的 cat 就打印 hi。Linux 0.11 的 stat.h 里有 S_IFIFO，root 用 mknod 也建得出这样的 i 节点，可 read、write 只认匿名管道，读写它都返回 -EINVAL。
      • 
    
    
  
    

    



    
  
    
    12
    
    写文件：echo hi > /tmp/a 改了硬盘上的哪几块
    
    
    读文件只是查表，写文件要改表。新建一个文件，要在 i 节点位图里找一个空位，再在目录里加一项；写进内容，要在区块位图里再找一个空位。改过的块先在缓冲区里标成“脏”的，攒到 sync 时一起写回硬盘。下面的块号和 i 节点号都是真机上的。
    
  
    
  
    
    
    
    
    
    
    
    
    
    
    展开细节：当前目录、文件系统锁、删掉开着的文件
      
      
    • 当前目录：每个任务记着当前目录的路径，fork 时照抄。路径不是 / 开头的，系统调用先把它接在当前目录后面，再交给 namei()。. 和 .. 不用特别处理：它们本来就是每个目录里的头两项，/etc/.. 查到的就是根目录，根目录的 .. 指向它自己。
      • 
      
    • cd 先确认目标是一个目录，再按字面去掉多余的 /、. 和 .. 存起来，所以 cd /bin/../etc/./ 之后 pwd 打印 /etc。cd 必须是 shell 的内建命令：fork 出子进程去换目录，换的只是子进程自己的，子进程一结束就没了。
      • 
      
    • Linux 0.11 的 current->pwd 记的是当前目录的 i 节点，没有 getcwd 系统调用，pwd 要沿着 .. 一级级往上，在上一级目录里找自己的名字。这里记的是路径，getcwd 直接复制出来就行。
      • 
      
    • 文件系统锁：读写硬盘会睡，两个任务同时改文件系统，可能分到同一块。所以改文件系统的操作、读文件、查路径、exec 装入程序，都要先拿到一把锁。Linux 0.11 给每个 i 节点、每个缓冲区各加一把锁，并发更好，道理相同。
      • 
      
    • 延迟写回：同一块（位图、i 节点表、目录）连着改好几次，最后只写一次。脏块在缓冲区要换成别的块时先写回，或者等 sync：init 每隔大约 5 秒调用一次。突然关机，最多丢掉最近几秒的修改。Linux 0.11 也是标脏（b_dirt），用户态的 update 进程每 30 秒 sync 一次。
      • 
      
    • 修改时间：开机时从 CMOS 读出日期和时间，之后靠定时器往前数。写文件、在目录里加项删项，就把 i 节点的修改时间改成现在；ls -l 显示它，touch 把它改成现在。i 节点里只有这一个时间，和 Linux 0.11 的 Minix 文件系统一样。
      • 
      
    • 删掉开着的文件：目录里那一项清掉了，打开它的程序还能接着读写；最后一个描述符关掉时，链接数是 0，才真正放掉它的块和 i 节点。
      • 
    
    
  
    

    



    
  
    
    13
    
    信号：按下 Ctrl+C 之后
    
    
    信号是内核通知进程“出了某件事”的办法。按 Ctrl+C，终端给前台进程组里的每个进程挂上 SIGINT。shell 让每条命令自成一个进程组，运行时把终端的前台交给它，所以 Ctrl+C 只到得了正在运行的命令。进程回到用户态之前，内核看它怎么处理：没设处理函数的，就此结束；设了的，内核改写它的用户栈，让它先去调用处理函数，回来以后再接着往下走。
    
  
    
  
    
    
    
      
    
        
    
        
    
      
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 每个任务属于一个进程组，fork 时继承。init 拉起 shell 时，子进程先 setsid() 开一个新的会话、自成一组，再打开 /dev/tty0：会话的头打开终端，终端就成了它的控制终端，这一组是前台进程组。init 和写 C 的 letter 不在这个会话里，Ctrl+C 到不了它们。Linux 0.11 的 init() 也是先 setsid() 再打开终端。
      • 
      
    • shell 运行命令时，子进程 setpgid 自成一组，shell 用 ioctl 的 TIOCSPGRP 把终端的前台换成这一组；命令结束或者停下，再换回自己。后台的命令（&）不是前台，Ctrl+C 到不了它，要用 kill 任务号（SIGTERM）、kill %1 或者 kill -9（SIGKILL，不能忽略）。脚本里的 sh 不管作业，命令都在它自己的组里：后台的那些在 exec 之前把 SIGINT 改成忽略，忽略的信号 exec 之后还是忽略。Linux 0.11 的 exec 把所有信号都改回默认，连忽略的也改回来；这里照 POSIX 的规定。
      • 
      
    • 往读的一头全关了的管道里写，写的进程收到 SIGPIPE，默认就被结束，和 Linux 0.11 的 write_pipe() 一样。
      • 
      
    • 闹钟：alarm(秒数) 记下到期的时刻，定时器中断查到闹钟到了，就发 SIGALRM；pause() 睡到来了一个信号为止。/bin/sleep 就是给 SIGALRM 设个处理函数、定好闹钟、pause 等它，早年 Unix 的 C 库里的 sleep() 也是这样写的。睡着的时候按 Ctrl+C，SIGINT 照样结束它。
      • 
      
    • 处理函数是普通的 C 函数，只会改 eax、ecx、edx 和标志，所以内核只保存这几个；sig_restore 就是 Linux 0.11 的 libc 里的 __sig_restore。Linux 0.11 的 signal() 设的处理函数只管一次（SA_ONESHOT），这里一直有效。
      • 
      
    • 任务 0、A 和 init 收不到信号：前两个是内核任务，从不回到用户态，信号永远处理不了；init 要收养孤儿、拉起 shell，不能结束。
      • 
    
    
  
    

    



    
  
    
    14
    
    堆：sort 要来的内存
    
    
    sort 要把所有的行都读进来才能排序，事先不知道要多少内存。它用 brk 把“堆”的末尾往上推，内核只记下这个数；真正写到哪一页，缺页时才补哪一页。堆和栈之间没要过的地方不补：用到那里就是程序的错。
    
  
    
  
    
    
    
      
    
      
    
        
    
        
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • brk(addr) 不能低于程序的末尾，最高到栈区往下 16 KB，做不到就不动，返回现在的末尾；brk(0) 就是问“堆到哪儿了”。fork 照抄父进程的堆，exec 换了程序，堆从新程序的末尾重新开始。
      • 
      
    • malloc 是用户程序自己的代码（user/ulib.c）：堆上的块一个挨一个，每块前面 8 个字节记着大小、空着没有；先找够大的空块（路上把挨着的空块并起来），大得多就切开，找不到就 sbrk 一块新的；free 把块标成空的，和后面紧挨着的空块并成一块；realloc 遇到堆末尾的块，直接往上推 brk。
      • 
      
    • 挪低 brk 也不收回已经补上的页，进程结束时 free_page_dir() 一起收回。Linux 0.11 的 sys_brk() 也只是记下这个数，页同样在缺页时由 do_no_page() 补上；不过它数据段以上的地方缺页都补，不区分堆和栈。
      • 
    
    
  
    

    



    
  
    
    15
    
    作业控制：Ctrl+Z、bg 和 fg
    
    
    shell 把每条命令放进一个新的进程组，叫作一个作业。前台作业运行时，终端的前台进程组就是它，Ctrl+C、Ctrl+Z 只发给它。Ctrl+Z 发的是 SIGTSTP，进程的默认动作是停下：不结束，也不再被调度。shell 从 waitpid 知道它停了，记进作业表；bg 让它在后台接着运行，fg 再把终端交还给它。
    
  
    
  
    
    
    
      
    
        
    
        
    
      
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 停下的任务状态是 T（TASK_STOPPED）：不在等任何东西，也不会被调度，直到收到 SIGCONT 或者 SIGKILL。停着的时候来的别的信号先挂着，接着运行以后再处理。SIGSTOP 和 SIGKILL 一样拦不住，SIGTSTP 可以接住或者忽略：shell 自己就忽略它，在提示符上按 Ctrl+Z 什么也不发生。
      • 
      
    • waitpid(pid, &st, WUNTRACED) 不光等子进程结束，也等它停下，状态是 0x400 加信号编号（Ctrl+Z 是 0x414），一次停下只报告一次。不带 WUNTRACED 的 waitpid 看不见停下。
      • 
      
    • 后台作业要读终端，会收到 SIGTTIN 停下：cat & 马上就停了，jobs 里是 stopped，fg 以后才能读。写终端不管，后台的输出照样印在屏幕上。
      • 
      
    • 停着的作业，shell 退出了就没人能让它接着运行。这种“孤儿进程组”里只要有停着的，内核就给组里每个进程发 SIGHUP 和 SIGCONT，把它们结束。
      • 
      
    • 管道是一个作业：cat | wc 两个进程在同一组，Ctrl+Z 一起停，fg 一起接着。kill %1 是 shell 的内建命令，发给整个组，停着的再补一个 SIGCONT。
      • 
      
    • Linux 0.11 已经有 setpgid、getpgrp 和终端的 TIOCSPGRP，任务状态里也有 TASK_STOPPED，waitpid 也认 WUNTRACED；可是没有谁让进程停下：do_signal() 对没有处理函数的信号（SIGCHLD 除外）一律结束进程，终端也不发 SIGTSTP。
      • 
    
    
  
    

    



    
  
    
    16
    
    用户与权限：读不了的 /etc/shadow
    
    
    每个进程带着用户号和组号：实际的说明是谁运行的，有效的用来检查权限。每个文件记着主人、组和 9 个权限位。打开文件时，内核按有效用户号挑出一组 rwx 来比，root 什么都行。setuid 程序运行时，有效用户号换成文件的主人：passwd 就是这样替普通用户改只有 root 能写的 /etc/shadow。
    
  
    
  
    
    
    
      
    
        
    
        
    
      
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 用户和组的名字在 /etc/passwd、/etc/group 里，内核只认数字。ls -l 打印的就是数字：0 是 root，100 是 user。
      • 
      
    • 密码不存原文：/etc/shadow 里每行是用户名和“用户名:密码”的散列（64 位的 FNV-1a，重复算 1000 遍）。只能演示“只存散列”的道理：真正的系统要用专门设计得很慢的算法和随机的盐。
      • 
      
    • 查路径时，经过的每一个目录都要有 x；在目录里新建、删除一项，要对目录有 w 和 x。/tmp 是 drwxrwxrwt：谁都能在里面建文件，可最后那个 t 是粘滞位，删别人的文件不行，只有文件的主人、目录的主人和 root 能删。
      • 
      
    • root 也执行不了一个执行位都没有的文件。chmod 只有主人和 root 能改；chown 只有 root 能改，换了主人，setuid 位跟着清掉，免得别人的程序变成以自己的身份运行。
      • 
      
    • 串口上是 login：问用户名和密码，对了就 setgid、setuid 成那个用户，进他的家目录，运行他的 shell。setuid 只能从 root 往下换，换完了就回不去：先换组再换用户，顺序反了就没有权限换组了。
      • 
      
    • Linux 0.11 的 i 节点里也有 uid、gid 和权限位，permission() 也是按有效用户号挑一组 rwx 来比，只是 root 连执行位都不看。setuid、setgid 系统调用它也有；login、su 是用户程序，不在内核里。
      • 
    
    
  
    

    



    
  
    
    17
    
    内存：用到才装入，不够就换出去
    
    
    exec 不把程序读进内存，只记下程序文件和它的几个段；程序用到哪一页，缺页时才从文件读那一页。同一个程序运行两份，只读的页共用一份。物理页快用完了，内核挑一阵子没用过的页让出来：没写过的直接扔掉，用到时再从文件读；写过的写到硬盘尾部的交换区，用到时再读回来。
    
  
    
  
    
    
    
      
    
        
    check 的页表（用户空间的前几页）
    
        
    
      
    
      
    
        
    物理页
    
        
    
        
    交换区：
    
        
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 程序的页从哪里读：任务记着程序文件的 i 节点和每个段在文件里的位置、在内存里的地址、要多大、能不能写。缺页的地址落在哪个段里，就从文件对应的位置读一页；文件里没有的部分（.bss）补 0。读文件要睡，缺页处理先开中断。
      • 
      
    • 共用只读的页：先看看有没有别的进程正在运行同一个程序文件、已经读进了这一页，有就直接映射那个物理页，引用数加一（第 3 行的 shared）。可写的页每个进程一份。Linux 0.11 的 do_no_page() 也是先 share_page()，不行再从文件读。
      • 
      
    • 程序文件要一直留着：运行着的程序引用着它的 i 节点，删掉名字也照样运行；运行着的程序不能打开来写（返回 ETXTBSY），开着写的程序也不能运行。
      • 
      
    • 挑哪一页换出去用时钟算法：一根指针在所有任务的用户页上转圈，访问位（CPU 用到这一页时置上）是 1 的清掉、再给一次机会；共用的页不换。脏位（CPU 写这一页时置上）说明要不要写盘：内核按物理地址往页里写的地方（exec 放参数的那一页、写时复制复制出来的页）自己把脏位置上。
      • 
      
    • 换出去的页表项：存在位是 0、整个又不是 0，高 20 位是交换页的号加一。存在位是 0 时 CPU 不看别的位。fork 时照抄给子进程，交换页的引用数加一，谁先用到谁读回一份。
      • 
      
    • 什么时候换：缺页、fork、exec、pipe 这些能睡的地方，空闲页少于 16 页就先换出去一些。留着的十几页给关着中断、不能睡的地方用。自检只留 300 页物理内存，让一个进程用 2 MB 的堆、再 fork、再 exec，换出去的页读回来都对，最后交换区一页不剩。
      • 
      
    • Linux 0.11 已经按需装入、共用代码页，但没有交换，物理页用完了 get_free_page() 就返回 0。0.12 加了 mm/swap.c：分不到页就调用 swap_out()，也是转着圈找一页，没写过的放开，写过的写到交换设备上。
