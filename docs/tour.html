从上电到用户态

按下电源后，要经过好几段代码接力，一个普通程序才能在受保护的环境里运行。屏幕第一行每多出一个字母，就说明又走通了一段。

    01
    
    开机：把程序从软盘搬进内存
    
    
    CPU 只能执行内存里的代码，而程序都躺在软盘上。三段程序像接力一样，每一段把下一段搬进内存，再把执行权交给它。
    
  
    
  
    
    
    
    
    
    
    
    
    展开细节
      
      
    • BIOS 只认“柱面、磁头、扇区”（CHS）地址。loader 先用 int 0x13 AH=08h 问出每道 18 个扇区、2 个磁头，再把 LBA 换算：扇区 = LBA mod 18 + 1，磁头 = (LBA ÷ 18) mod 2，柱面 = LBA ÷ 36。例如 LBA 20 是柱面 0、磁头 1、扇区 3。
      • 
      
    • 每次只读 512 字节，目标地址按 512 对齐，永远不会跨越 64 KB 边界（软驱 DMA 的限制）。读失败先复位磁盘再试，最多 3 次。读完关掉软驱马达。
      • 
      
    • 读多少个扇区由 Makefile 按 kernel.bin 的实际大小算出，在汇编 loader 时传进去。
      • 
      
    • Linux 0.11 的 bootsect.s 做的是同一件事：把 setup 读到 0x90200，把内核读到 0x10000。
      • 
    
    
  
    

    



    
  
    
    02
    
    换挡：从 16 位实模式到 32 位保护模式
    
    
    开机时 CPU 模仿 1978 年的 8086，只能看见 1 MB 内存，也没有任何保护。要用上 4 GB 地址和特权级，得按顺序拨动五个开关，CPU 计算地址的方法也随之完全改变。
    
  
    
  
    
    
    
      
    
        
    实模式 16 位 · 1 MB
    
        
    段 0x1000× 16 +偏移 0x0042=0x10042
    
        
    • 地址直接由段值算出，最大约 1 MB
    • 任何代码都能读写任何地址
    • 可以调用 BIOS 读盘、显示字符
    
      
    
      
      
        
    1. cli先关中断：切换时还没有新的中断表
      2. 
        
    2. 打开 A20第 21 根地址线默认被屏蔽，不开就够不着 1 MB 以上
      3. 
        
    3. lgdt告诉 CPU 段描述符表在哪里
      4. 
        
    4. CR0.PE = 1这一位一置上，就进入保护模式
      5. 
        
    5. jmp 0x08:…远跳转换上新的代码段，开始执行 32 位代码
      6. 
      
    
      
    
        
    保护模式 32 位 · 4 GB
    
        
    选择子 0x08→GDT 第 1 项 基址 0+偏移 0x10042=0x10042
    
        
    • 段寄存器里放的是表的下标，基址和界限查表得到
    • 有特权级：内核 0 级，用户程序 3 级
    • BIOS 不能再用，只能直接写显存
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • loader 里的 GDT 只有 3 项：空描述符、代码段 0x08、数据段 0x10，基址都是 0、界限 4 GB（平坦段），所以偏移就等于物理地址。
      • 
      
    • 进入内核后，gdt_init() 换上内核自己的 10 项 GDT：除了这两段，还有 3 个 TSS 和两个 DPL 3 的用户段（0x33、0x3B）。
      • 
      
    • A20 用端口 0x92 打开；Linux 0.11 的 setup.s 用的是更老的键盘控制器方法。
      • 
    
    
  
    

    



    
  
    
    03
    
    开张：内核一项项准备好
    
    
    内核拿到 CPU 后，按固定顺序把各个部件准备好。顺序很要紧：比如中断表没装好就开中断，第一次中断就会让 CPU 重启。右边是每一步之后屏幕第一行的样子。
    
  
    
  
    
    
    
    
    
  
    

    



    
  
    
    04
    
    中断：硬件怎样打断 CPU
    
    
    CPU 不会一直盯着键盘。按键时，信号沿着一条固定的路传过来，CPU 放下手里的事，查表找到处理函数，处理完再回到原处。
    
  
    
  
    
    
    
      
    
        
        
      
    
      
    
    
    
    
    
    
  
    

  
    
    
    处理之前，先把现场存到栈上
    
    
    
      
    
        
        
      
    
    
    
    
    
      
    
      
    
        
    
        
    CPU 自动压入入口 isrN 压入isr_common 压入
    
        
    
      
    
    
    
    
    展开细节
      
      
    • 压完以后，从栈顶往上看正好是 C 语言里的 struct interrupt_frame，于是把栈顶地址当参数交给 interrupt_dispatch()，C 代码就能读写被打断时的每个寄存器。系统调用的返回值就是改写其中的 EAX 交回去的。
      • 
      
    • BIOS 把键盘、定时器的中断号放在 0x08～0x0F，正好撞上 CPU 异常 8～15。pic_init() 重新设置 8259，把它们挪到 0x20～0x2F，Linux 0.11 的 setup.s 做的是同一件事。
      • 
      
    • interrupt_dispatch() 先回 8259 一个 EOI（处理完了），它才会送下一个中断。必须先发再处理：定时器处理函数可能切换任务，新任务不会回到这里补发。
      • 
    
    
  
    

    



    
  
    
    05
    
    分页：每个地址都要翻译一次
    
    
    打开分页后，程序用的地址只是一个门牌号。CPU 把它拆成三段，查两张表，才知道真正的内存位置；查不到或没有权限，就触发缺页异常。挑一个地址试试。
    
  
    
  
    
    
    
    
    
      
    
      
    
    
    
    
    
      
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • 页目录和页表各有 1024 项，每项 4 字节，一张表正好一页（4 KB）。一张页表管 4 MB，4 张页表一一对应地映射前 16 MB：虚拟地址等于物理地址，所以打开分页的那一刻代码照常运行。
      • 
      
    • 第 0 页故意不映射，空指针一碰就出错；0xC0000000 也映射到显存，同一块内存有了两个地址，第 0 行的 V 就是从这个地址写进去的。
      • 
      
    • 只有用户程序那两页打开了用户位，其中代码页只读。CPU 要求页目录项和页表项两层都允许才放行。内核在特权级 0 不受只读位限制（CR0.WP 为 0）。
      • 
      
    • 缺页时，CPU 把出错的地址放进 CR2；错误码的三位分别表示：页存在吗、是写吗、来自用户态吗。
      • 
      
    • Linux 0.11 不靠页表的用户位隔离内核：它的页表把内核也标成了用户可访问，靠的是每个进程的段基址和界限。
      • 
    
    
  
    

    



    
  
    
    06
    
    轮流：谁在等，就把 CPU 让出去
    
    
    任务 A、B 写一个字母就调用 sleep(2)。内核把它标成睡眠，马上执行一条 ljmp 切到别的任务：CPU 把当前寄存器存进这个任务的快照（TSS），再装入下一个任务的快照。两个都睡着了，就切回空闲的任务 0，CPU 停在 hlt 上。定时器每 10 毫秒响一次，谁睡到时间就叫醒谁；一直不睡的任务，用完 20 个 tick 的时间片也会被强行切走。
    
  
    
  
    
    
    
      
    
      
    
      
    
    
    
    
      
    
        CPU
        
    
        
    
        
    
        
    
        
    任务 A任务 B空闲
    
      
    
      
    
    
    
    
    
    
    
    
    展开细节
      
      
    • TSS 是 CPU 规定格式的 104 字节。GDT 第 3、4、5 项分别指向任务 0（开机时的 kmain）、A、B 的 TSS，选择子 0x18、0x20、0x28。
      • 
      
    • sleep 先把任务标成睡眠、记下醒来的 tick，再调用 reschedule() 切走，这两步之间关着中断。Linux 0.11 的 sleep_on() 也是先改 current->state，再调用 schedule()。
      • 
      
    • 空闲比例是抽样算出来的：每个 tick 看一眼此刻谁占着 CPU。Linux 0.11 的 do_timer() 用同样的办法给当前进程记 utime、stime。正常运行时接近 100%：两个任务每 2 个 tick 才醒来写一个字母。
      • 
      
    • 被叫醒的任务不会马上抢走别人的 CPU，要等正在运行的任务睡下或用完时间片。Linux 0.11 也是这样：do_timer() 只在当前进程的 counter 减到 0 时才调用 schedule()。
      • 
      
    • CR3 只装入不保存，每个 TSS（包括任务 0 的）都要预先填好页目录地址。审查时发现任务 0 的漏填了：切回任务 0 时，CPU 会把物理地址 0 当成页目录，直接三重错误重启。现在每 2 个 tick 就要切回任务 0 一次，不修这个问题内核根本跑不起来。
      • 
    
    
  
    

    



    
  
    
    07
    
    隔离：用户程序与内核之间有一道墙
    
    
    任务 B 是一个普通程序，运行在特权级 3。它碰不到内核的内存，也不能执行关中断这类指令。想在屏幕上写一个字母，唯一的办法是穿过墙上那扇门：执行 int 0x80 发起系统调用，由内核检查之后替它去写。
    
  
    
  
    
    
    
      
    
        
        
        
      
    
      
    
    
    
    
    
    
    
    
      
    直接读写内核内存页表里内核的页没有用户位→ #PF，任务被结束
    
      
    改写自己的代码用户代码页是只读的→ #PF，任务被结束
    
      
    执行 cli、hlt、in、out特权指令，EFLAGS 的 IOPL 为 0→ #GP，任务被结束
    
      
    把内核地址交给 write内核先检查指针是否在用户的页里→ 返回 -1
    
    
    
    
    展开细节
      
      
    • 穿过门时 CPU 要换栈：用户栈不可信，CPU 从任务 B 的 TSS 取出 ss0:esp0，换到它的内核栈，再压入用户态的 SS、ESP、EFLAGS、CS、EIP。返回时 iret 看见 CS 的低 2 位是 3，就把这几项弹回去，回到用户态。
      • 
      
    • 调用约定和 Linux 0.11 一样：EAX 是调用号，EBX、ECX、EDX 是参数，返回值放回 EAX。现在有 write、getpid、sleep、exit 四个调用。
      • 
      
    • 用户程序出错只结束它自己：内核在第 7 行写一行黄字，把任务标记为已结束，切到下一个任务。NMI、双重错误、机器检查来自硬件，不算用户程序的错，照样显示红色异常面板。
      • 
      
    • Linux 0.11 不逐个检查用户指针：内核通过用户数据段（FS）读用户内存，越界由段界限挡住。这里所有段都是平坦的，只能显式检查。
      •
